## Status claimed

`verified`. Implemented bounded frame recording through the evidence store for remote terminal sessions. Exact timestamped frames (`stdin`, `stdout`, `resize`, `close`) are recorded in an in-memory buffer bounded at 10 MiB, transitioning cleanly to a marker frame when capped. Upon session close, disconnect, or timeout sweep, the session frames are finalized and sealed into an AES-256-GCM encrypted evidence bundle (`session_frames.ndjson`) with envelope key wrapping and an Ed25519-signed integrity receipt in the evidence store, immediately freeing in-memory buffers. Enforced fail-closed route gates rejecting static API keys on terminal and response routes (`403 Forbidden`) and rejecting external frame injection (`403 Forbidden`). Verified tenant isolation and role permissions (`admin`, `operator`, `auditor`). Fully verified under `-race` tests, Debian package lifecycle rehearsal, and live headless Google Chrome 150 execution against the packaged production hub on LXC 150.

## Claims

1. **Exact Timestamped Frame Capture**:
   - `RecordFrame` accepts typed `TerminalFrame` records (`stdin`, `stdout`, `resize`, `close`) and records UTC millisecond-precision timestamps.
   - Streaming data is routed strictly through authenticated WebSocket relays. External HTTP frame injection (`POST /api/v1/terminal/frames`) is rejected fail-closed with `403 Forbidden`.

2. **Per-Session Byte Bounding & Bounded Marker**:
   - Configurable per-session frame cap (default `10 MiB` / 10,485,760 bytes).
   - Once cumulative frame payload and overhead exceeds the cap, `recording_state` transitions to `"bounded"`.
   - Appends a standardized bounded marker frame: `"\r\n[Recording limit reached (10 MiB cap). Further stream frames bounded.]\r\n"`.
   - Silently drops subsequent raw stream frames to prevent memory exhaustion and disk exhaustion.

3. **Encrypted Evidence Store Sealing & Receipt Chaining**:
   - On session termination (explicit `DELETE`, WebSocket disconnect, or idle/duration timeout sweep), `SealSessionRecording` serializes buffered frames into newline-delimited JSON (`application/x-ndjson`).
   - Stores artifact `session_frames.ndjson` into the tenant's evidence bundle via `evidence.Store.StoreItem`.
   - Encrypts payload with an ephemeral 256-bit AES-GCM data key wrapped by the store master key with authenticated additional data (AAD) binding tenant ID, bundle ID, and item ID.
   - Finalizes evidence bundle with an Ed25519 signed integrity receipt (`receipt_signature` 64-byte Ed25519 signature over SHA-256 manifest and storage object digests chained to previous receipt).
   - In-memory frames buffer is zeroed and freed (`sess.Frames = nil`), transitioning state to `"sealed"`.
   - Durable metadata persisted in SQLite `terminal_sessions` (`bundle_id`, `evidence_item_id`, `recording_state`, `recording_bytes`, `frame_count`).

4. **On-Demand Decrypted Playback & Retrieval**:
   - `GetSessionRecording` checks session state: returns in-memory frames for active sessions, or transparently decrypts and parses `session_frames.ndjson` from the evidence store for sealed sessions.
   - Exposes recording metadata (`bundle_id`, `evidence_item_id`, `recording_state`, `recording_bytes`, `frame_count`, `encryption`).

5. **Strict Security & Route Isolation Gates**:
   - Static API keys (`X-Auth-Method: api-key`) are strictly forbidden on `GET /api/v1/terminal/sessions`, `POST /api/v1/terminal/sessions`, `DELETE /api/v1/terminal/sessions`, `POST /api/v1/terminal/sessions/close`, and `GET /api/v1/terminal/frames`. Only authenticated operator response sessions or JWT bearer tokens are permitted.
   - Enforced tenant boundaries: sessions from other tenants cannot be inspected or decrypted (`403 Forbidden` / `ErrTenantMismatch`).
   - Role permissions: `auditor` role has read-only access to list sessions, view recording metadata, and inspect frames; mutating actions require `operator` or `admin`.
