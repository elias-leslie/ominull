# v1.8.29 UDP observation evidence

Verified 2026-09-07. Linux now observes UDP through BPF and Windows consumes
kernel-network ETW events. Neither path invents conversations from socket tables.
Queue limits, fair draining, process attribution, timing and collector gaps are
specified in [UDP observation coverage](../UDP_OBSERVATION.md).

## Native and regression checks

- Linux 6.8 isolated dual-stack echo: TCP plus four UDP rollups, ten payload
  bytes in and out per family. Pressure fixture: 280 records from 140 closed
  sockets, no loss, no extra records from repeated `MSG_PEEK`.
- Linux 6.17 isolated network namespace: eight UDP records, ten bytes in and
  out per family, no collector loss.
- Windows 11 native ETW pressure: 560 records, 700 payload bytes in and out
  per family. Exact fixture totals passed; no unexpected loss. Link-local
  observations without interface scope are separately counted omissions.
- Windows crash recovery passed. A deliberately mismatched recorded session
  GUID returned error 13 and left that trace running; restoring its ownership
  record allowed cleanup. No session was stopped by name alone.
- Full 64-record JSON fixtures preserved IPv6 and escaped paths. Linux's
  worst-case control-character fixture produced valid 628,630-byte JSON.
- Go regression tests exercised protocol-separated detection, invalid cadence,
  collector gaps, bounded histories, observation persistence and validation.
  Full race tests and vet passed. Native build, package, JavaScript syntax,
  version, hygiene and secret checks passed. Only the documented historical
  secret-scanner finding remained.

## Production observations

The canonical hub-first release updated all six online agents to 1.8.29 with
native package provenance. The release wait expired with exactly the two known
powered-off Windows endpoints outdated and zero provenance issues.

A nonempty `/api/v1/traffic/flows` UDP response reported 631 total rows and
returned 200: 192 from `linux-bpf-udp`, eight from `windows-etw-udp`. Both sources
had real process IDs and nonzero payload counts. Every inspected row had protocol
17, a positive observation count, an ordered interval and timestamp equal to its
last observation. `/api/v1/detection/coverage` reported seven bandwidth windows,
two beacon windows, zero evictions and an 8,192-entry capacity.

Four Linux agents reported active BPF coverage. One container reported BPF
unavailable with error -1; its TCP collector remained active. Windows reported
active ETW with scope omissions explicitly included in dropped counts. Container
privileges were not changed. Active does not establish complete traffic capture.

The actual production Traffic page rendered its timeline and UDP protocol share
in the managed headless browser. Browser console and error output were empty.
Screenshots remain private because they contain real estate data. This verifies
page rendering and live telemetry, not the pending topology redesign. Native
loopback/isolated tests do not verify production IPv6 enforcement.
