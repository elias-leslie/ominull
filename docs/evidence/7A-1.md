# Evidence: Slice 7A — Authoritative Software Inventory Collection & Ingestion Pipeline

## 1. Overview

Slice 7A implements authoritative installed software inventory collection across Linux and Windows endpoints, tenant-scoped and source-aware database storage, deduplication by package identity, and paginated query APIs on the Hub.

Every inventory record preserves both raw values and normalized values:
- **`source`**: Authoritative system source (`dpkg`, `rpm`, `win_registry`, `msi`, `snap`, etc.). Scanner banners remain strictly segregated from authoritative host package inventory.
- **`product` & `raw_product`**: Normalized product identifier alongside verbatim system package name (`Package` from dpkg status, `DisplayName` from Windows registry).
- **`version` & `raw_version`**: Normalized version string alongside verbatim upstream version string (`Version`, `DisplayVersion`).
- **`vendor` & `raw_vendor`**: Normalized vendor name (`debian`, `ubuntu`, `redhat`, `microsoft`, `google`, etc.) alongside verbatim system maintainer or publisher field (`Maintainer`, `Publisher`).
- **`architecture`**: Hardware or packaging architecture (`amd64`, `all`, `x64`, `x86`).
- **`install_scope`**: System-wide installation (`system`) vs per-user installation (`user`).
- **`confidence`**: Provenance classification (`authoritative` vs `inferred`).
- **`observed_at`**: Local UTC observation timestamp.

## 2. Implementation Architecture

### 2.1 Linux Endpoint Package Collector (`agent/include/software_inventory_linux.h`)
- Reads `/var/lib/dpkg/status` in streaming chunks.
- Identifies package stanzas separated by blank lines and filters strictly on `Status`:
  - Must end with `installed` (e.g. `install ok installed`).
  - Ignores `deinstall`, `purge`, and `not-installed` packages.
- Normalizes maintainer names into vendor namespaces (`ubuntu`, `debian`, `canonical`, `redhat`, `microsoft`, `google`, etc.) while retaining the full verbatim `raw_vendor` string.
- RPM fallback: If `/var/lib/dpkg/status` is absent and RPM databases (`/var/lib/rpm` or `/usr/lib/sysimage/rpm`) are present, safely executes `rpm -qa --qf '%{NAME}\t%{VERSION}-%{RELEASE}\t%{ARCH}\t%{VENDOR}\n'` via `popen()`.
- Generates JSON payloads with zero memory leaks and bounded allocation limits via `SoftwareInv_SerializeJSON()`.

### 2.2 Windows Endpoint Package Collector (`agent/include/software_inventory_windows.h`)
- Enumerates installed software from Windows registry hives:
  1. `HKLM\Software\Microsoft\Windows\CurrentVersion\Uninstall` (64-bit native on x64)
  2. `HKLM\Software\Wow6432Node\Microsoft\Windows\CurrentVersion\Uninstall` (32-bit WoW64 on x64)
  3. `HKCU\Software\Microsoft\Windows\CurrentVersion\Uninstall` (per-user installs)
- Queries `DisplayName`, `DisplayVersion`, `Publisher`, `WindowsInstaller`, `SystemComponent`, and `ParentKeyName`.
- Ignores child patches / sub-components (`ParentKeyName`) and internal GUID keys without display names to prevent duplicate or phantom records.
- Identifies Windows Installer packages (`WindowsInstaller == 1`) with source `msi`.
- Normalizes publisher names while preserving raw registry values.
- Respects stack bounds: batch allocated on heap (`calloc`) preventing Win32 stack overflow.

### 2.3 Endpoint Daemon Integration
- **Linux Daemon (`agent/linux/main.c`)**:
  - Implements `SyncSoftwareInventory()` posting to `/api/v1/software` using `RunHubCurl()`.
  - Executes on startup and periodically every 3,600 seconds (1 hour).
- **Windows Daemon (`agent/src/service.c`)**:
  - Implements `SyncSoftwareInventoryWin()` posting to `/api/v1/software` using `Hub_PostPathJSON()`.
  - Executes on startup and periodically every 3,600,000 milliseconds.

### 2.4 Hub Database Schema & Store (`hub/pkg/vuln/store.go`, `dto.go`)
- Table `software_inventory` with additive columns:
  - `install_scope TEXT DEFAULT 'system'`
  - `confidence TEXT DEFAULT 'authoritative'`
  - `raw_vendor TEXT DEFAULT ''`
  - `raw_product TEXT DEFAULT ''`
  - `raw_version TEXT DEFAULT ''`
- Safe column addition via `ensureColumn(db, table, col, colType)` to support seamless migrations over existing databases.
- Unique source-aware index:
  `idx_software_identity ON software_inventory(tenant_id, endpoint_id, source, product, version, architecture)`
  Ensures exact deduplication without merging distinct software packages or distinct sources.
- Full query support:
  `ListSoftwareInventory(filter SoftwareFilter) (*SoftwareInventoryPage, error)`
  Filters by `tenant_id`, `endpoint_id`, `source`, and `search` (substring match on product, vendor, raw_product) with limit and offset pagination.
- Full deletion support:
  `DeleteSoftwareInventory(tenantID, endpointID string) error`

### 2.5 Hub REST API (`hub/pkg/server/vuln_handlers.go`)
- `GET /api/v1/software`: Paginated retrieval of software inventory for an endpoint or tenant. Supports `endpoint_id`, `source`, `search`, `limit`, `offset`.
- `POST /api/v1/software`: Ingests endpoint software inventory batch. Accepts both `packages` and legacy `items`, supports replacing all or replacing by `source`.
- `DELETE /api/v1/software`: Removes software inventory for an endpoint.

## 4. Security & Isolation Invariants
- **No Banner Mixing**: Scanner banners remain strictly separated from authoritative host package inventory. Scanner discoveries are never injected into `software_inventory`.
- **Bounded Ingestion**: Ingestion JSON is bounded, streams cleanly, and avoids unbound memory growth.
- **Tenant Isolation**: Every database read, write, and deletion query strictly enforces `tenant_id = ?`.
- **Stack Protection**: Linux and Windows batch structs are heap-allocated via `calloc` to prevent stack overflows under bounded thread stack environments.
