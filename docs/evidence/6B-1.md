# Evidence: Slice 6B — Linux Endpoint Process Lineage, Boot Identity Binding, & Executable Hashing

## 1. Overview

Slice 6B delivers kernel boot identity binding, bounded `/proc` lineage inspection, user-space LRU executable SHA-256 hashing, explicit attribution status semantics, and telemetry batch serialization for the Linux endpoint daemon (`ominulld`).

Every active TCP/IP socket flow captured by the Linux collector is enriched with the complete execution provenance:
- **`process_instance_id`**: Unambiguous string identifier `<boot_id>:<pid>:<starttime>` preventing PID reuse collisions.
- **`parent_pid`**: Authoritative parent PID from `/proc/<pid>/stat` (field 4).
- **`parent_process_instance_id`**: Verifiable parent instance ID `<boot_id>:<ppid>:<parent_starttime>` or omitted when the parent process has already terminated (zero synthesis of unverified tree state).
- **`command_line`**: Null-delimited arguments parsed from `/proc/<pid>/cmdline`, converted into space-separated string with zero-allocation JSON escaping.
- **`user_identity`**: Real UID extracted from `/proc/<pid>/status` and resolved to username via thread-safe `getpwuid_r` (with fallback to `UID:<num>`).
- **`executable_sha256`**: In-process cryptographic SHA-256 digest computed from safely opened `/proc/<pid>/exe` backing inode.
- **`attribution_status`**: Explicit status classification: `authoritative`, `inferred_cached`, `race_suspected`, `permission_denied`, or `unknown`.
- **`observed_at`**: RFC3339 timestamp of the local observation.

## 2. Implementation Architecture

### 2.1 Boot Identity Binding & Process Instance IDs (`agent/include/process_lineage_linux.h`)
- Boot ID resolution reads `/proc/sys/kernel/random/boot_id` or falls back to `/proc/stat` `btime`.
- In-process caching guarantees consistent identity across heartbeats.
- Process instance IDs format as `${boot_id}:${pid}:${starttime}`:
  - If a PID is recycled within the same boot, kernel `starttime` (clock ticks since boot from `/proc/<pid>/stat` field 22) separates the instances.
  - If the machine reboots, `boot_id` changes, isolating cross-boot timeline analyses.

### 2.2 Robust `/proc` Stat & Comm Parsing
- The Linux kernel allows process `comm` strings to contain arbitrary whitespace and closing parentheses.
- Parsing locates the final `)` delimiter using `strrchr(line, ')')`, correctly anchoring field 3 (`state`), field 4 (`ppid`), and field 22 (`starttime`).

### 2.3 User-Space Executable Hash Cache (512 Entries)
- Keyed on file inode identity tuple: `(st_dev, st_ino, st_size, st_mtime)`.
- File size capped at 64 MiB (`LINUX_MAX_HASH_BYTES`) to avoid blocking background telemetry collection on oversized binaries.
- If a binary matches cache, the SHA-256 hex is served immediately with status `inferred_cached` without disk reads.
- On cache miss, file contents are streamed through `ResponseSHA256Context`, converted to hex, stored in the LRU slot, and reported as `authoritative`.
- Full cache evicts the oldest LRU slot based on monotonically increasing access sequence counter.

### 2.4 Race & Permission Handling (Zero False Inventions)
- If `/proc/<pid>/stat` or `/proc/<pid>/exe` is missing due to rapid exit, `attribution_status` is marked `race_suspected`.
- If permission is denied (`EACCES`/`EPERM`), status is marked `permission_denied`.
- If parent process has exited, `parent_pid` is preserved while `parent_process_instance_id` is left empty rather than inventing unverified start times.

### 2.5 Daemon Wiring (`agent/linux/main.c`)
- Flow event struct `LINUX_FLOW_EVENT` embeds `PROCESS_ENRICHMENT enrichment`.
- `CollectActiveFlows` inspects each unique PID in the batch with intra-batch PID deduplication.
- `SendTelemetryBatch` serializes enrichment fields into telemetry JSON payload with `ProcessLineage_EscapeJSON`.
