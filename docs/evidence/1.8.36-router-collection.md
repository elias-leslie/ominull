# v1.8.36: router collection replaces hub listeners

Phase 3 removes the hub DNS forwarder, passive DHCP listener, their startup
flags, DNS management routes and console panel. Router DNS events and
name-to-address resolutions remain available for attribution.

Router leases now contribute their own identity claims without deleting scanned
ports. Client-supplied DHCPv4 options 55 and 60 are stored with the event time
and router provenance, visible in asset identity claims. They do not become
unverified operating-system guesses. Equal-confidence scan/router claims use
the newest observation; agent and operator precedence remains unchanged.

The OpenWrt hook uses dnsmasq's structured lease-script environment instead of
parsing interleaved log lines. Existing OpenWrt hotplug handlers remain intact.
See [installation and bounds](../../scripts/router/README.md).

The unused `alerts` table retires only when empty. Unexpected legacy rows survive
upgrades that skipped the grace release. Retention no longer references that
table. Current findings remain in `anomaly_alerts`.

port evidence, missing DHCP fingerprint claims, stale scan claims hiding newer
lease names, empty-table retirement, and retention after retirement. A stronger
freshness assertion also caught SQLite timestamp parsing before deployment;
comparison now uses decoded `time.Time` values under the store lock.

## Runtime evidence and limits

Canonical release deployed the hub first, verified Linux and Windows canaries,
then updated every endpoint online at rollout. Native provenance passed.
The two known powered-off laptops remain outdated with queued jobs; final fleet
waiting stopped after verifying the online set, without claiming full-fleet
convergence.

On the reference IPv4 LAN:

- DNS resolution passed before and after enabling the gateway hook. Installed
  hook and poller hashes match the repository.
- A natural lease event supplied option 55. The hub accepted router leases,
  flows, DNS events and resolutions with no rejected rows in the observed poll.
- `/api/v1/assets` contains router claims and the natural option-55 fingerprint.
- `/api/v1/dns/status`, `/api/v1/dns/events`, `/api/v1/dns/policy` and
  `/api/v1/dns/policy/test` return 404.
- The legacy table is absent; current findings and router DNS tables retain rows.
- The hub listens on its console/API ports, with no DNS or DHCP listener.
- Production `app.js?v=1.8.36` renders Traffic summary cards and flow rows,
  without the retired DNS panel or DNS-management requests. Asset expansion
  displays DHCP options with router provenance and the DHCP observation time.

Option 60, malformed-input cases, stale/new evidence, scan-port preservation,
and upgrade variants were verified with synthetic fixtures. The observed live
client supplied no option 60. No IPv6 production verification is claimed.
