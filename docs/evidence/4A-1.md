## Claims

1. **Allowlisted Linux Diagnostic Profile Collectors**:
   - Implemented 8 dedicated collectors in `agent/include/forensics_linux.h`:
     1. `os_version.json`: Parses `/etc/os-release` and `uname()` kernel release info.
     2. `network_interfaces.json`: Queries system network interfaces using `getifaddrs()` reporting MAC address, IPv4, IPv6, MTU, and interface flags.
     3. `routes.txt`: Reads `/proc/net/route` and `/proc/net/ipv6_route`.
     4. `dns_config.txt`: Reads `/etc/resolv.conf`.
     5. `resource_summary.json`: Reads `/proc/meminfo` and `/proc/loadavg` for system memory and load averages.
     6. `service_state.json`: Reads `/proc` to enumerate running system processes and names.
     7. `system_logs.txt`: Captures bounded tail of `/var/log/syslog` or system journal (capped at 512 KiB).
     8. `agent_diagnostics.json`: Reports running agent PID, uptime, binary path, configuration, and telemetry state.
   - Collectors return honest status values: `collected`, `empty`, `unsupported`, `permission_denied`, `truncated`, `timed_out`, or `failed`.
   - Strict size bounds: 512 KiB per artifact, 10 MiB cumulative cap for diagnostic bundle.

2. **Contained Child Worker Isolation**:
   - In `agent/linux/main.c`, forensic collection runs in an isolated fork child worker.
   - `setpgid(0, 0)` prevents signals from propagating to or from the parent daemon.
   - File descriptors > 2 are closed to prevent leaking telemetry sockets or database handles to child tasks.
   - Environment sanitized via `clearenv()`, setting only safe `PATH=/usr/bin:/bin` and `LANG=C`.
   - Working directory fixed to safe `/var/lib/ominull`.
   - `setrlimit(RLIMIT_CPU, ...)` bounds total CPU consumption to 60 seconds.
   - Child status and manifest SHA-256 returned to parent via an internal unidirectional pipe.

3. **Pure-C In-Process TweetNaCl Ed25519 Manifest Signing**:
   - Added detached Ed25519 signing (`Ed25519_Sign`) and keypair generation (`Ed25519_CreateKeypairFromSeed`) to `agent/include/ed25519_verify.h` using in-process TweetNaCl algorithms. Zero external library dependencies.
   - Endpoint evidence signing key generated and stored at `/var/lib/ominull/evidence_signer.key` with file mode `0600`.
   - Agent advertises public key in periodic heartbeat telemetry batches (`evidence_signing_key`), persisted in SQLite `endpoints.evidence_signing_key`.
   - Canonical binary manifest format V2 starts with magic prefix `OMINULL-MANIFEST-V2\0`, followed by length-prefixed big-endian string headers (`tenant_id`, `endpoint_id`, `bundle_id`, `profile`, `timestamp`), item count, and per-item descriptors (`relative_path`, `content_type`, `size`, `sha256`).
   - Manifest signed with endpoint private key; signature and public key sent to `/api/v1/evidence/bundles/finalize`. Hub verifies endpoint signature before issuing signed hub receipt.

4. **Fail-Closed Response Route Security & Bundle Auto-Provisioning**:
   - `POST /api/v1/response/jobs` checks `r.Header.Get("X-Auth-Method") == "api-key"` and rejects static API keys with `403 Forbidden` (`{"error":"static API keys cannot launch response actions; an active console response session is required"}`).
   - For `forensic_collection` jobs, hub automatically ensures an evidence bundle exists with `id = job.ID` via `CreateBundleWithID(..., OnConflictDoNothing)` to guarantee atomic bundle availability when endpoint uploads items.
   - Agent acknowledges job offer with `"accepted": true`, uploads each artifact via chunked HTTP upload (`POST /api/v1/evidence/items`), signs manifest, and finalizes bundle. Hub chains signed hub receipt.
