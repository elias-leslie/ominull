## Status claimed

`verified`. Implemented the web console script library UI, dynamic schema-driven parameter form generator, browser-native WebCrypto Ed25519 signing for script execution, single job output inspection modal with stdout/stderr visualization, and schedule freezing:
1. **Fail-Closed Console Execution Gate**: `POST /api/v1/scripts/run` and `POST /api/v1/scripts/schedules` strictly refuse static API keys (`403 Forbidden`). Only authenticated console operators with an active Response Authority session can dispatch or schedule script executions.
2. **Web Console Script Library UI**: Implemented full library management in `hub/pkg/server/web/app.js`:
   - "New Script" creation sheet with syntax-highlighted code editor, interpreter picker (`/bin/bash`, `/bin/sh`, `powershell.exe`, `cmd.exe`, `pwsh`), description, and typed JSON parameter schema editor with template inserter.
   - Version history inspection sheet displaying version numbers, timestamps, SHA-256 immutable digests, and verbatim source code.
   - Per-row "Run", "Versions", and "Retire" actions with confirmation modals.
3. **Dynamic Parameter Form Generator**: Inspects the script's `parameter_schema_json` and dynamically generates typed HTML form controls:
   - `enum`: `<select>` dropdown populated with allowed choices.
   - `boolean`: checkbox input with true/false state.
   - `number`: numeric input with `min`/`max` constraints.
   - `ipv4` / `cidr` / `string`: validated text inputs with regex pattern matching.
   - Injects field labels, descriptions, default values, and required indicators.
4. **WebCrypto Ed25519 ActionProof V2 Signing**:
   - Queries `POST /api/v1/scripts/digest` to obtain canonical server-computed `action_digest` and `script_digest`.
   - Signs `ActionProof` V2 in-browser using WebCrypto Ed25519 private key stored exclusively in browser session memory.
   - Dispatches execution to `POST /api/v1/scripts/run`, seamlessly transitioning to the live Job Output modal.
5. **Live Job Output Inspection Modal**:
   - Fetches individual job details via `GET /api/v1/response/jobs?id=<job_id>`.
   - Metadata grid displaying Job ID, Endpoint ID, Status Badge (`badge-ok` / `badge-err`), Exit Code, Duration (ms), and Requested At.
   - Formatted monospace stdout and stderr console blocks with one-click copy buttons and truncation notices.
   - Auto-polls every 2 seconds until terminal state (`succeeded` / `failed`) is achieved, with automated interval cleanup on sheet dismissal.
6. **Schedule Freezing (Immutable Script Digest & Explicit Endpoint Snapshot)**:
   - `script_schedules` SQLite schema and store methods implemented with full CRUD and race-detector verification.
   - Gated endpoints `GET|POST|DELETE /api/v1/scripts/schedules`.
   - When a schedule is created, it freezes the script version's exact `script_digest` and creates an explicit snapshot array of target endpoint IDs (dynamic wildcards strictly prohibited).
   - "Frozen Script Schedules" card in console displaying schedule ID, recurrence, target endpoints snapshot, frozen digest, run count, status, and cancel action.
   - Backend cancel endpoint marks schedules as `cancelled`, preventing further execution.

## Claims

1. **Fail-Closed API Key Rejection**:
   - Static API keys attempting to call `POST /api/v1/scripts/run` or `POST /api/v1/scripts/schedules` receive HTTP 403 Forbidden with descriptive error messages.
2. **Dynamic Parameter Form Validation**:
   - Forms dynamically render from typed schemas and prevent submission if required fields are missing, numeric bounds are violated, or regex patterns do not match.
3. **Cryptographic ActionProof V2 Integrity**:
   - Script execution requests must supply an `ActionProof` V2 signed by the operator's browser session Ed25519 key matching the registered session public key.
4. **Schedule Freezing Integrity**:
   - Scheduled executions lock down the immutable `script_digest` and snapshot target endpoints at creation time, ensuring later script edits or fleet shifts cannot execute unexpected code.
5. **Real-Time Output Inspection**:
   - Monospace terminal viewing displays raw stdout and stderr without HTML escaping distortion, accurately reflecting process output and termination codes.
