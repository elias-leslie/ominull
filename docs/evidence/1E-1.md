## Claims

1. **Subcommand Architecture & Token Invariants**:
   - `ominullctl` organizes operations into clean subcommand groups: `endpoints`, `scanner`, `alerts`, `mesh`, `agents`, `install`, `response`, `response-auth`, `forensics`, `scripts`, `shell`, `software`, and `vulnerabilities`.
   - Setup token operations (`setup-token`, `setup-status`) inspect private regular files using `O_NOFOLLOW` with file permission checks (`0600`), without network transmission or API key requirements.
   - Removed insecure plaintext `OMINULL_API_KEY` environment variable ingestion; authenticates exclusively through local private key file (`--api-key-file` or `OMINULL_API_KEY_FILE`, defaulting to `/etc/ominull/admin.key`).
2. **Complete Parity with `scripts/ominull-cli`**:
   - Retained command parity:
     - `status`: fetches both `/api/v1/hierarchy` and `/api/v1/endpoints`, rendering overall hub health, active tenants, and managed endpoints.
     - `scan` / `scanner scan`: initiates subnet sweeps with specified profile (`standard` / `aggressive`).
     - `assets` / `scanner assets`: retrieves discovered subnet assets, vendors, and OS classifications.
     - `train` / `scanner train`: submits ground-truth feedback to train fingerprinting models.
     - `alerts`: lists active behavioral threat detections.
     - `quarantine-mesh` / `mesh quarantine`: enforces lateral subnet mesh isolation.
     - `unquarantine-mesh` / `mesh release`: lifts lateral subnet mesh isolation.
     - `agent-versions` / `agents versions`: reports fleet agent version currency.
     - `agent-update` / `agents update`: dispatches versioned agent release updates to specific endpoints or fleet-wide.
     - `install-errors` / `install reports`: retrieves bootstrap installer error logs.
   - Direct top-level aliases are preserved so existing operational workflows remain fully functional.
3. **Forensics & Response Inspection**:
   - `response jobs list`: inspects active and completed response jobs across the fleet.
   - `response jobs cancel <id>`: issues cancellation requests for in-flight response jobs.
   - `response-auth status`: checks the availability and health of the isolated Response Authority.
   - `response-auth recovery-token`: safely rotates and generates local emergency recovery tokens.
   - `forensics list`: lists completed forensic collections.
   - `forensics verify <manifest>`: cryptographically validates local forensic manifest files.
4. **Console-Only Mutation Protection**:
   - Console-only operations requiring dual-operator authorization are strictly forbidden in `ominullctl`:
     - `shell open`, `shell exec`, `shell attach` fail with explicit authorization error.
     - `scripts run`, `scripts schedule` fail with explicit authorization error.
     - `forensics launch`, `forensics collect` fail with explicit authorization error.
   - Eliminates automated single-key API execution of high-risk mutations.
5. **Zero References & Removal of Legacy Bash Script**:
   - Removed `scripts/ominull-cli`.
   - Updated documentation (`README.md`, `PLAN.md`) to guide operators toward `ominullctl`.
   - Zero broken references remain across codebase, packaging, and scripts.
