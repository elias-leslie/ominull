## Status claimed

`verified`. Enforced sanitized path construction (`filepath.Base(it.Name)`) preventing path traversal during archive extraction. Exported tar.gz archives now bundle `bundleID/manifest.json` and `bundleID/receipt.json` alongside decrypted evidence items for self-contained validation. Enforced a 10GB streaming limit per export (`maxExportBytes`), prevented false audit logging upon streaming failures (`EVIDENCE_EXPORT_FAILED`), sanitized download filenames, and verified offline catalog inspection and Ed25519 signature checks using `ominullctl forensics verify`.

## Claims

1. **Safe Archive Path Hierarchy**:
   - `ExportBundleToTarGz` constructs header paths as `filepath.Join(bundleID, filepath.Base(it.Name))`, strictly rejecting path traversal sequences (`../`, absolute paths).
   - Bundles `bundleID/manifest.json` and `bundleID/receipt.json` inside the archive so extracted packages can be independently verified without contacting the hub.
2. **Streaming Limits**:
   - Export streams track cumulative bytes streamed and fail closed with `ErrQuotaExceeded` if total export exceeds the 10GB ceiling (`maxExportBytes`).
3. **Honest Failure Auditing**:
   - Updated `handleEvidenceExport` in `hub/pkg/server/evidence_handlers.go` so mid-stream failures trigger `s.audit(r, "EVIDENCE_EXPORT_FAILED", bundleID, ...)`. The successful audit `EVIDENCE_EXPORTED` is only written when the stream completes cleanly.
   - Download `Content-Disposition` filenames sanitize endpoint IDs using strict regex and safe bounding on the bundle prefix.
4. **Offline Verification**:
   - Validated that `ominullctl forensics verify` checks manifest digests against extracted local files, validating Ed25519 signatures from both the collecting endpoint and the hub receipt signer.
