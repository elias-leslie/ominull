# v1.8.30 IPv6 parity evidence

Verified 2026-09-08 UTC. This completes Phase 2, before the planned topology
replacement. Collection, policy semantics and remaining limits are documented in
[IPv6 agent collection and isolation](../IPV6_AGENT_PARITY.md).

## Native checks

- Windows TCP collection observed real cross-guest ULA and scoped link-local
  connections. Each controlled echo produced one measured IPv6 observation with
  exactly 4,096 bytes in and out. Interface scope matched the connected socket.
- Windows WFP used a separate dynamic test sublayer. Four reachable IPv4/IPv6
  services established the precondition. Default deny permitted both configured
  hub addresses only on the specified TCP port. IPv6 peer blocks took precedence
  over allow entries, invalid scope preserved prior rules, and release retained
  peer quarantine and hub recovery. Final cleanup restored connectivity.
- Removing the IPv6 neighbor cache exposed a real isolation failure before the
  link-control fix. The same cold-cache test passed afterward on Windows and in
  isolated Linux namespaces. Linux also passed exact dual-stack hub ports,
  IPv6 block precedence and release.
- Fail-first fixtures covered missing Windows IPv6 enumeration, policy parsing,
  scoped JSON, primary-adapter selection, WFP transaction rollback and Linux
  forensic IPv6 addresses. Parser fixtures exercised complete A/AAAA resolution,
  deduplication, over-capacity rejection and unsupported scoped destinations.
- Full Go race tests and vet passed; the server package took 226.628 seconds.
  Native build, packaging, JavaScript syntax, version, managed project checks,
  whitespace, hygiene and staged secret checks passed. The history secret scan
  retained only the documented finding in commit 665795f.

## Production observations

The canonical hub-first release updated both canaries, then all six online agents
reported 1.8.30. `/api/v1/agents/update-status` returned eight retained endpoint
rows, exactly two known offline laptops outdated, and zero provenance issues.
The release script exited 1 when its five-minute fleet wait expired on those two
laptops. This is not a claim that the entire retained fleet converged.

`/api/v1/endpoints` returned 11 rows including retired endpoints. All six online
agents were non-isolated. Windows ESTATS and ETW were active. Four Linux BPF
collectors were active; the existing container limitation remained explicitly
unavailable with error -1 while its TCP collector stayed active.

A production Windows TCP request to `/api/v1/traffic/flows` with `range=1h`
reported 415 total rows and returned 200, all sourced from `windows-estats`.
That sample contained no IPv6 rows. Native IPv6 collection and enforcement checks
above are controlled runtime evidence, not a claim of production IPv6 enforcement.

`/api/v1/baseline/endpoint` returned the new intrinsic IPv6 link-control permit.
The actual managed-browser Assets detail view displayed it in the "If isolated"
table alongside hub recovery and loopback. The screenshot was visually inspected;
browser console and error output were empty. Screenshots and raw fleet evidence
remain private. No topology implementation is included in this checkpoint.

The local preview server and Linux echo process were stopped, and both temporary
network namespaces removed. Windows test processes had exited and the installed
agent service remained running. Failure logs and test files were retained.

## Limits

Linux firewall chain replacement remains sequential and non-atomic. Router
advertisement renewal and path-MTU feedback were not separately exercised.
Windows UDP ETW still reports scoped-address omissions because its schema lacks
an interface index. None of these limits was hidden by changing privileges or
claiming full capture.
