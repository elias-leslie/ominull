## Status claimed

`verified`. Implemented retention enforcement engine (`PruneExpiredBundles`) with physical disk cleanup for unreferenced encrypted storage objects. Verified that `legal_hold` status provides absolute retention immunity, preserving expired bundles and their stored artifacts indefinitely until released. Enforced operator accountability by capturing `legal_hold_actor` and `legal_hold_reason` on every hold transition with audit logging (`EVIDENCE_LEGAL_HOLD_TOGGLED`). Added admin pruning API (`POST /api/v1/evidence/prune`) and `ominullctl forensics prune` command. Verified with comprehensive unit test suites in `store_test.go` and `evidence_test.go`.

## Claims

1. **Retention Enforcement Engine**:
   - `PruneExpiredBundles(now time.Time)` identifies bundles where `retention_expires_at <= now` and `legal_hold = 0`.
   - In SQLite transaction, cascades deletion across `evidence_chunks`, `evidence_items`, `evidence_receipts`, and `evidence_bundles`.
   - Identifies orphaned `storage_digest` values and safely removes the underlying encrypted object files from disk.
2. **Legal Hold Immunity & Actor Attribution**:
   - Bundles under active legal hold (`legal_hold = 1`) are strictly exempt from pruning, even after `retention_expires_at` has passed.
   - `SetLegalHold` records both the operating actor identity and the legal/compliance reason in dedicated bundle columns (`legal_hold_actor`, `legal_hold_reason`) and writes `EVIDENCE_LEGAL_HOLD_TOGGLED` to the audit log.
3. **Prune API & CLI Integration**:
   - Exposed `POST /api/v1/evidence/prune` requiring admin credentials. Non-admin calls fail closed with 401/403.
   - Emits structured audit log `EVIDENCE_PRUNED` recording the count of purged bundles.
   - Integrated into CLI via `ominullctl forensics prune`.
