## Status claimed

`verified`. Deployed the packaged `ominull-hub_1.8.3_amd64.deb` to the live hub host (LXC 150) under snapshot protection (`pre-slice-3-0c`). Configured dedicated console listener on `:8443` with `OMINULL_CONSOLE_HOSTNAME=hub.example.invalid`. Exported the internal Hub Root CA and installed it into the client workstation system trust store (`/usr/local/share/ca-certificates/`) and user NSS database (`~/.pki/nssdb`). Verified that standard TLS handshakes succeed without insecure flags or overrides (`curl -i https://hub.example.invalid:8443/api/v1/console/status`). Launched a real headless Google Chrome 150 browser instance without `--ignore-certificate-errors` pointing to the non-localhost origin (`https://hub.example.invalid:8443`), proving:
1. `window.isSecureContext === true` on remote non-localhost origin;
2. `window.crypto.subtle` ECDSA P-256 keypair generation, signing, signature verification, and SHA-256 digest computation;
3. `window.PublicKeyCredential` passkey credential registration (`navigator.credentials.create`) with relying party ID (`hub.example.invalid`) and origin binding (`origin: https://hub.example.invalid:8443`);
4. W3C WebAuthn §5.4.3 RP ID invariant rejection: passing an IP address origin as RP ID is rejected fail-closed with `SecurityError: The relying party ID is not a registrable domain suffix of, nor equal to the current domain.`

## Claims

1. **Live Host Package Deployment & Service Verification**:
   - Created safety rollback snapshot `pre-slice-3-0c` on Proxmox hypervisor (`10.0.0.39`).
   - Installed `ominull-hub_1.8.3_amd64.deb` in LXC 150 (`10.0.0.58`).
   - Configured `OMINULL_CONSOLE_TLS_LISTEN=:8443` and `OMINULL_CONSOLE_HOSTNAME=hub.example.invalid` in `/etc/ominull/hub.env`.
   - `ominull-hub.service` active and serving dedicated HTTPS console interface on `:8443` alongside `:9443` agent mTLS and `:9999` cleartext API.
2. **Dedicated Console Security & HSTS**:
   - `GET /api/v1/console/status` confirms `client_auth: NoClientCert`, `source: hub-ca`, `hostname: hub.example.invalid`, `webauthn_rp_id: hub.example.invalid`, and `hsts: true`.
   - Server returns `Strict-Transport-Security: max-age=31536000; includeSubDomains`.
3. **Guided Root Trust in Operating System & Browser**:
   - Hub Root CA downloaded from `/api/v1/pki/ca.crt` and registered in Debian `/usr/local/share/ca-certificates/` via `update-ca-certificates`.
   - Imported into user NSS certificate database (`~/.pki/nssdb`) with SSL trust flags (`C,,`).
   - Standard `curl` validates TLS without `-k` or custom `--cacert`.
4. **Real Browser Secure Context & WebCrypto Verification**:
   - Google Chrome 150 connected to `https://hub.example.invalid:8443/` without `--ignore-certificate-errors`.
   - `window.isSecureContext` is `true`.
   - `window.crypto.subtle.generateKey` generated ECDSA P-256 keypair (91-byte SPKI).
   - `window.crypto.subtle.sign` produced 64-byte ECDSA signature and `window.crypto.subtle.verify` returned `true`.
   - `window.crypto.subtle.digest("SHA-256", ...)` returned 32-byte digest.
5. **Real Browser WebAuthn & RP ID Invariant Verification**:
   - Platform authenticator available (`isUserVerifyingPlatformAuthenticatorAvailable: true`).
   - Passkey creation succeeded with RP ID `hub.example.invalid`: returned credential type `public-key`, clientDataJSON origin `https://hub.example.invalid:8443`.
   - Passing an IP address as RP ID threw `SecurityError`, proving browser enforcement of WebAuthn domain constraints.
