## Status claimed

`verified`. Built-in TOTP enrollment and authentication has been hardened with AES-256-GCM secret encryption at rest, 5-attempt lockout enforcement, single-use 30-second timestep anti-replay, root emergency recovery token consumption, and honest phishing-vulnerability security labeling.

## Claims

1. **Secret Encryption at Rest**:
   - Master 32-byte key generated and stored at `/var/lib/ominull-response-authority/secret.key` with file mode `0600` owned by `ominull-authority:ominull-authority`.
   - All enrolled TOTP secrets encrypted with AES-256-GCM before writing to the durable `authenticators` table.
   - Proved on live production container LXC 150 that `secret_or_key` contains hex-encoded GCM ciphertext, not plaintext base32.
2. **Single-Use Timestep Anti-Replay**:
   - `VerifyTOTPCodeWithStep` matches the exact 30-second counter window.
   - Timestep is registered in `used_nonces` table with TTL.
   - Re-submitting the same code or any code within the same 30-second window is rejected with `ErrTOTPReplayed` ("TOTP code already used for this 30-second window; wait for next timestep").
3. **Attempt Limits & Lockout**:
   - Tracked in `authenticators.failure_count`.
   - After 5 failed attempts (`MaxFailedAttempts`), authenticator is locked for 15 minutes (`LockoutDuration`).
   - Subsequent unlock attempts fail with `ErrAuthenticatorLocked` even if the submitted code is valid.
4. **Root Emergency Recovery**:
   - Added `ResetLockoutWithRecovery` and `/v1/auth/recovery/consume` endpoint.
   - Consumes single-use SHA-256 hashed recovery tokens to clear lockout and reset failure count.
   - Replay of consumed recovery token is rejected with `ErrTokenUsed`.
5. **Honest Security Labeling**:
   - Authenticators are labeled with `SecurityLabelTOTP` (`Phishing-Vulnerable (RFC 6238 Shared Secret)`), distinguishing them from WebAuthn hardware credentials as required by `RESPONSE_THREAT_MODEL_AND_TRUSTED_ORIGIN.md`.
