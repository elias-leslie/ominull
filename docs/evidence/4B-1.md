## Status claimed

`verified`. Implemented the `live_volatile` forensic collection profile on both Linux and Windows. Collectors capture allowlisted volatile system state via native operating system APIs and virtual filesystems with honest status attribution (`collected`, `empty`, `unsupported`, `permission_denied`, `truncated`, `timed_out`, `failed`), individual byte caps (512 KiB per artifact), cumulative bundle caps (10 MiB), and execution timeouts. Unified collection runners (`Forensics_RunCollection` on Linux, `Forensics_RunCollectionWin` on Windows) dynamically dispatch to either `diagnostic` or `live_volatile` profiles while sharing unified bundle finalization logic (`Forensics_PublishBundleAndFinalize` / `Forensics_PublishBundleAndFinalizeWin`). Manifests are encoded into canonical length-prefixed binary format (`OMINULL-MANIFEST-V2\0`) and signed in-process via TweetNaCl detached Ed25519 using persistent endpoint evidence keys. Verified via pure-C tests (`-Wall -Wextra -Werror`) on Linux and Windows (under MinGW and Wine), Go Hub end-to-end integration tests under the race detector (`TestServer_LiveVolatileForensicFlow`), and full native package builds and lifecycle rehearsals.

## Claims

1. **Linux Live Volatile Profile Collectors**:
   - Implemented 6 allowlisted volatile state collectors in `agent/include/forensics_linux.h`:
     1. `process_snapshot.json`: Traverses `/proc/[0-9]+`, parses `/proc/<pid>/stat` (PID, comm, state, PPID, threads, start time), `/proc/<pid>/cmdline` (argv string), `/proc/<pid>/status` (UID, GID, VmRSS, VmSize), and `/proc/<pid>/exe` (`readlink`). Employs dynamic truncation handling: if output reaches 512 KiB, it stops parsing further processes, closes the JSON array, and reports status `truncated`.
     2. `socket_to_process.json`: Scans `/proc/[0-9]+/fd` links to pre-populate an in-memory socket-inode-to-(PID, comm) mapping cache, parses `/proc/net/tcp`, `/proc/net/udp`, `/proc/net/tcp6`, and `/proc/net/udp6`, correlating network sockets to owning processes and TCP states (`ESTABLISHED`, `LISTEN`, `CLOSE_WAIT`, etc.).
     3. `logged_in_sessions.json`: Reads and parses `/run/utmp` via `<utmp.h>` for active `USER_PROCESS` sessions (user, tty/station, remote host, PID, login timestamp). Automatically falls back to inspecting `/run/systemd/sessions` if utmp is unavailable or empty.
     4. `network_neighbors.json`: Parses `/proc/net/arp`, resolving IP address, HW type, flags (mapping `0x2` to `reachable`, `0x0` to `incomplete`, `0x4` to `stale`), MAC address, and network interface device.
     5. `firewall_state.json`: Reads active filter tables from `/proc/net/ip_tables_names`, executes contained non-shell `/usr/sbin/iptables-save -c` and `/usr/sbin/ip6tables-save -c` via `Forensics_RunCommandCapture` with strict output size bounding, and inspects whether Ominull containment chains (`OMINULL_QUARANTINE`) are present.
     6. `loaded_modules.json`: Parses `/proc/modules`, capturing kernel module name, memory size, reference count, and dependency list.
   - All collectors enforce strict memory bounding (512 KiB per artifact, 10 MiB cumulative cap).

2. **Windows Live Volatile Profile Collectors**:
   - Implemented 6 allowlisted volatile state Win32 collectors in `agent/include/forensics_windows.h`:
     1. `process_snapshot.json`: Uses `CreateToolhelp32Snapshot(TH32CS_SNAPPROCESS, 0)` with `Process32First` / `Process32Next`, `OpenProcess`, `QueryFullProcessImageNameA` for full binary path, and `GetProcessMemoryInfo` (linking `-lpsapi`) for `WorkingSetSize` and `PagefileUsage`.
     2. `socket_to_process.json`: Dynamically binds and executes `GetExtendedTcpTable` (`TCP_TABLE_OWNER_PID_ALL`) and `GetExtendedUdpTable` (`UDP_TABLE_OWNER_PID`), correlating local/remote endpoints, TCP state, and owner PID.
     3. `logged_in_sessions.json`: Uses Windows Terminal Services API (`WTSEnumerateSessionsA`, `WTSQuerySessionInformationA` with `WTSUserName`, `WTSWinStationName`, `WTSClientName`, `WTSConnectState`, linking `-lwtsapi32`) with graceful fallback to `GetUserNameA` if WTS is unavailable.
     4. `network_neighbors.json`: Uses `GetIpNetTable` from `iphlpapi.dll`, mapping ARP cache IP addresses, physical MAC addresses, interface indexes, and entry types (`dynamic`, `static`, `invalid`).
     5. `firewall_state.json`: Inspects Windows Defender Firewall registry keys under `HKLM\SYSTEM\CurrentControlSet\Services\SharedAccess\Parameters\FirewallPolicy` for Domain, Standard, and Public profiles (`EnableFirewall`, `DoNotAllowExceptions`).
     6. `loaded_modules.json`: Enumerates loaded kernel device drivers via `EnumDeviceDrivers`, `GetDeviceDriverBaseNameA`, and `GetDeviceDriverFileNameA`.
   - All collectors report honest collector statuses and enforce 512 KiB item bounds.

3. **Dynamic Profile Dispatching & Unified Bundle Finalization**:
   - Added `Forensics_RunCollection(profile, ...)` and `Forensics_RunCollectionWin(profile, ...)`, routing dynamically between `diagnostic` and `live_volatile` profiles based on the response job payload parameter `params.profile`.
   - Factored out unified bundle publishing and finalization (`Forensics_PublishBundleAndFinalize` and `Forensics_PublishBundleAndFinalizeWin`), guaranteeing consistent SHA-256 item hashing, length-prefixed canonical binary manifest V2 encoding (`OMINULL-MANIFEST-V2\0`), in-process TweetNaCl detached Ed25519 signing, and HTTP upload/receipt exchange across all profiles.

4. **Hub End-to-End Test & Archive Verification**:
   - Added `TestServer_LiveVolatileForensicFlow` in `hub/pkg/server/response_test.go`.
   - Exercises complete lifecycle: WebAuthn/TOTP unlocked session, typed ActionProof V2 signing, job creation with profile `live_volatile`, endpoint registration with Ed25519 evidence public key, telemetry offer reception, upload of all 6 live volatile artifacts, endpoint canonical manifest V2 signing, hub manifest verification and receipt generation, and `.tar.gz` export verification validating exact content matching of all 6 artifacts alongside `manifest.json` and `receipt.json`.

5. **Package Build & Lifecycle Rehearsal**:
   - Updated MinGW linker flags in `scripts/build.sh` and `scripts/build-packages.sh` with `-lpsapi -lwtsapi32`.
   - Rebuilt all artifacts and successfully verified `scripts/test-package-lifecycle.sh` without regression.
