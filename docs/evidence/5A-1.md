## Status claimed

`verified`. Hardened the Ominull script library subsystem end-to-end:
1. Implemented strongly-typed parameter schema definition and execution validation engine supporting `"string"`, `"number"`, `"boolean"`, and `"enum"` types with regex pattern validation, unique parameter names, bounds checks (8 KiB schema, 16 KiB parameter values, 64 KiB script source), strict allowlisting against undeclared parameter injections, and null-byte rejection.
2. Hardened the script storage layer with an immutable versioning model, strict interpreter allowlisting (`/bin/sh`, `/bin/bash`, `powershell.exe`, `cmd.exe`, `pwsh.exe`), tenant isolation across all query and mutation methods, and retired script mutation/execution prevention.
3. Hardened hub server routes (`/api/v1/scripts`, `/api/v1/scripts/run`): enforced tenant isolation, independent server-side SHA-256 payload digest recomputation, parameter schema validation, execution bounds clamping (1-300s timeout, max 5 MiB output), and fail-closed static API key gating (unconditionally returns HTTP 403 Forbidden; requires active console response session with browser-bound ActionProof V2).
4. Extended native CLI `ominullctl scripts` with full parity for script library management (`list`, `show`, `create`, `update`, `retire`) while enforcing fail-closed rejection on `run` and `schedule` (console-only dual-operator authorization).
5. Added unit and integration tests across `pkg/scripts`, `pkg/server`, and `cmd/ominullctl` with zero race conditions under `go test -race`. Verified package builds and Debian lifecycle rehearsals.

## Claims

1. **Parameter Schema Engine (`hub/pkg/scripts/schema.go`)**:
   - `ValidateSchema`: Verifies raw schema JSON syntax and size (<= 8 KiB), ensures parameter names match `^[a-zA-Z0-9_-]{1,64}$` without duplicates, validates regex compilation for string patterns, parses default values, and ensures enum definitions contain at least one valid option (supporting both `"enum"` and `"enum_values"` keys).
   - `ValidateParameters`: Enforces strict allowlisting (rejects any parameters not declared in the schema), checks required fields, verifies numeric formatting via `strconv.ParseFloat`, validates boolean values (`true`/`false`/`1`/`0`), verifies enum set membership, evaluates regex patterns, caps cumulative parameter value size at 16 KiB, and rejects null bytes (`\x00`).

2. **Script Store Hardening (`hub/pkg/scripts/store.go`)**:
   - Enforces `AllowedInterpreters` set: `/bin/sh`, `/bin/bash`, `powershell.exe`, `cmd.exe`, `pwsh.exe`. All other interpreters are rejected with `ErrInvalidInterpreter`.
   - Enforces `MaxScriptSourceBytes = 65536` (64 KiB) at both creation and version update.
   - Enforces tenant isolation on `CreateScript`, `UpdateScript`, `RetireScript`, `GetScript`, `GetScriptVersion`, and `ListScripts`.
   - Prevents cross-tenant leakage in version queries by joining the `scripts` table and verifying `s.tenant_id = ?`.
   - Prevents modification or execution of retired scripts (`ErrScriptRetired`).

3. **Server Route Hardening & Fail-Closed Gate (`hub/pkg/server/script_handlers.go`)**:
   - Gated execution (`POST /api/v1/scripts/run`): Static API keys (`X-Auth-Method == "api-key"`) are unconditionally rejected with HTTP 403 Forbidden (`"static API keys cannot execute scripts; an active console response session is required"`).
   - Only console response sessions with browser WebCrypto Ed25519 ActionProof V2 can authorize script dispatch.
   - Server-side independent SHA-256 digest recomputation over `response.ScriptExecPayload` matching the signed proof and Response Authority grant request.
   - Target endpoint tenant verification ensures cross-tenant dispatch is blocked.
   - Parameters are bounded: timeout clamped to 1-300s (default 60s), max output clamped to 1-5242880 bytes (default 1 MiB).

4. **Native CLI Parity (`hub/cmd/ominullctl/main.go`)**:
   - Implemented `scripts list`: Formats registered scripts with ID, name, latest version, interpreter, retirement status, and description.
   - Implemented `scripts show <id> [--version <v>]`: Displays script metadata and all version history, or detailed version metadata including parameter schema and complete source code.
   - Implemented `scripts create --name <name> --interpreter <interp> [--desc <desc>] --source-file <path|-> [--schema-file <path|->]`: Reads source and schema files and creates new script definition.
   - Implemented `scripts update <id> --source-file <path|-> [--schema-file <path|->]`: Appends new immutable version.
   - Implemented `scripts retire <id>`: Retires script.
   - Enforced fail-closed behavior: `scripts run` and `scripts schedule` unconditionally fail with an error stating script execution and scheduling are console-only and require dual-operator authorization.
