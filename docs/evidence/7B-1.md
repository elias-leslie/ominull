# Evidence: Slice 7B — Vulnerability Feed Ingestion & Versioned Snapshot Lifecycle

## 1. Overview

Slice 7B implements versioned feed snapshot lifecycles and authoritative vulnerability feed ingestion across:
1. **NVD 2.0 API**: Complete CVE definitions, CVSS v3.1 / v3.0 / v2 scoring metrics, English description extraction, and CPE match criteria configurations with version boundary ranges (`versionStartIncluding`, `versionStartExcluding`, `versionEndIncluding`, `versionEndExcluding`).
2. **CISA Known Exploited Vulnerabilities (KEV)**: Catalog entries with due dates, required action, date added, and ransomware campaign usage flags.
3. **FIRST Exploit Prediction Scoring System (EPSS)**: Exploit probabilities and percentiles merged by CVE ID.

Every sync operation executes under an **atomic snapshot isolation guarantee**:
- The active CVE catalog is **never written to directly** during ingestion.
- New data stages in an isolated snapshot state (`building`) in `snapshot_vulnerabilities` and `snapshot_cisa_kev`.
- Validation checks verify that the snapshot contains valid non-empty records.
- Promotion to `active` is atomic within a database transaction, demoting previous active snapshots to `superseded`.
- Any partial, corrupted, or rate-limited (HTTP 429) sync marks the building snapshot as `failed`, leaving the existing active snapshot completely untouched and operational.
- All historical snapshots remain queryable by `snapshot_id`, ensuring explainable and reproducible vulnerability assessments.

## 2. Implementation Architecture

### 2.1 Feed Parsers & Client Fetchers (`hub/pkg/vuln/feed.go`)
- **`ParseNVD20(r io.Reader) ([]Vulnerability, error)`** and **`ParseNVD20WithTotal`**:
  - Parses official NIST NVD 2.0 JSON format (`nvd20Envelope`).
  - Extracts CVSS v3.1, v3.0 base scores and severities.
  - Serializes CPE match criteria and version ranges into normalized JSON pattern strings.
- **`ParseCISAKEV(r io.Reader) ([]CISAKEVItem, error)`**:
  - Parses official CISA KEV JSON catalog (`catalogVersion`, `vulnerabilities`).
  - Validates non-empty catalog items.
- **`ParseEPSSJSON(r io.Reader) (map[string]EPSSScore, error)`**:
  - Parses FIRST EPSS API JSON data with scores and percentiles into a fast lookup map.
- **Network Fetchers**:
  - `FetchCISAKEV(ctx context.Context, client *http.Client, url string) ([]CISAKEVItem, error)`
  - `FetchEPSS(ctx context.Context, client *http.Client, url string) (map[string]EPSSScore, error)`
  - `FetchNVD20Page(ctx context.Context, client *http.Client, baseURL, apiKey string, startIndex, resultsPerPage int) ([]Vulnerability, int, error)`
  - `SyncFeeds(ctx context.Context, store *Store, opts FeedSyncOptions, snapshotID, metadata string) (*FeedSnapshot, error)`
  - Respects HTTP 429 Too Many Requests, bounded readers (`io.LimitReader`), custom User-Agent, and pagination parameters.

### 2.2 Snapshot Database Schema & Lifecycle (`hub/pkg/vuln/snapshot.go`, `store.go`)
- **`vuln_feed_snapshots`**:
  - `id`: Unique snapshot identifier (e.g. `snap-20260904-120000`).
  - `created_at`: Timestamp created.
  - `activated_at`: Timestamp promoted to active.
  - `status`: State machine: `building` -> `active` / `failed` / `superseded`.
  - `nvd_count`, `cisa_kev_count`, `epss_count`: Validated item counts.
  - `source_metadata`: JSON string indicating feed provenance.
  - `error_message`: Failure rationale on interrupted/rate-limited syncs.
- **`snapshot_vulnerabilities`**:
  - Snapshot-isolated vulnerability catalog with primary key `(snapshot_id, cve_id)`.
  - Indexed on `cve_id`, `(snapshot_id, is_kev)`, and `(snapshot_id, severity)`.
- **`snapshot_cisa_kev`**:
  - Snapshot-isolated CISA KEV records with primary key `(snapshot_id, cve_id)`.
- **Atomic Promotion (`ActivateSnapshot`)**:
  - Refuses to activate empty snapshots (0 CVEs).
  - Atomically marks previous `active` snapshots as `superseded`.
  - Updates target snapshot status to `active` with UTC timestamp.
  - Synchronizes the active view for instant endpoint correlation.

### 2.3 REST APIs (`hub/pkg/server/vuln_handlers.go`, `server.go`)
- **`POST /api/v1/vulnerabilities/sync`**:
  - Supports direct JSON vulnerability records or raw NVD 2.0, CISA KEV, and EPSS payloads.
  - Supports `online: true` automated feed pulling with pagination.
  - Returns snapshot ID, item counts, and activation status.
- **`GET /api/v1/vulnerabilities/snapshots`**:
  - Lists all snapshots with their status, timestamps, and record counts.
- **`GET /api/v1/vulnerabilities/snapshots/active`**:
  - Returns metadata for the currently active snapshot.
- **`GET /api/v1/vulnerabilities?scope=catalog`**:
  - Paginated catalog search supporting `snapshot_id`, `severity`, `is_kev`, `search`, `limit`, and `offset`.
  - Preserves backwards compatibility for endpoint correlation queries when `scope=catalog` is omitted.
