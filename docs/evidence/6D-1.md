# Evidence: Slice 6D — Web Console Process Lineage Tree, Executable Hash Telemetry, & Fleet Investigation UI

## 1. Overview

Slice 6D delivers the operator visualization surface for process lineage, kernel boot identity, executable cryptographic hashing, and process execution forensics across the Ominull Web Console.

Operators investigating network flows or endpoint assets can now inspect the complete execution context:
1. **Interactive Process Lineage Hierarchy Tree (`.process-lineage-tree`)**:
   - **Parent Process Node**: Displays parent PID (`PPID`), verifiable parent process instance ID (`<boot_id>:<ppid>:<starttime>`), or explicit zero-invention note if the parent exited prior to inspection.
   - **Tree Branch Connector**: Visual downward branch glyph (`↳`).
   - **Child / Observed Process Node**: Displays process PID, executable path, process instance ID, and attribution confidence badge.
2. **Attribution Status Badges (`.attribution-badge`)**:
   - Color-coded badges distinguishing kernel/ETW confidence levels:
     - `authoritative`: Direct OS kernel / ETW lineage capture (Green).
     - `inferred_cached`: Verified from stable filesystem inode / file ID LRU cache (Blue).
     - `race_suspected`: Short-lived process exited before socket inspection could resolve (Amber).
     - `permission_denied`: OS security boundary prevented access (Red).
     - `unknown`: Baseline or un-enriched observation (Muted).
3. **Executable SHA-256 Digest Badges (`.hash-badge`)**:
   - Cryptographic SHA-256 digest display (`<prefix>…<suffix>`) with full hex on hover.
   - One-click copy button with instant toast notification.
   - One-click "Filter Fleet by Hash" search button that instantly filters the entire flow stream.
4. **Monospace Command Line Inspector (`.cmdline-box`)**:
   - High-contrast, pre-formatted command-line inspector rendering full execution arguments without truncation, accompanied by an inline copy button.
5. **Process Forensics & Event Inspection Modal Sheet (`.sheet-forensics`)**:
   - Accessible via "Forensics Sheet ↗" on the Flow Investigation side drawer or "Inspect" in the Asset "Recent flows" table.
   - Renders structured cards:
     - Header: Action Verdict, Direction, Timestamp, Observed At (Host Clock), Endpoint, Protocol, Sockets, Volume.
     - Process Hierarchy & Instance Identity card.
     - Binary Provenance & Cryptographic Signature card.
     - Command Line Execution Arguments card.
   - Footer action buttons: "Filter Fleet by Hash", "Filter by User", "Filter by Process", "Close".
6. **Fleet Filter Bar Integration**:
   - Support for `Hash: <sha>`, `User: <name>`, and `Attribution: <status>` filter chips with interactive `×` removal.
   - Seamless query parity on backend endpoints: `GET /api/v1/traffic/flows?hash=...&user=...&attribution=...`.

## 2. Implementation Architecture

### 2.1 Web Console Frontend Components (`hub/pkg/server/web/app.js` & `app.css`)
- **`processAttributionBadge(status)`**: Generates accessible attribution badges with explanatory tooltips.
- **`processHashBadge(hash, onSearch)`**: Generates pill badge with digest, copy trigger (`copyText`), and search trigger.
- **`processLineageTree(item)`**: Builds the parent -> child hierarchical tree DOM nodes.
- **`commandLineInspector(cmdline)`**: Wraps monospace command line in styled `<pre><code>` with copy utility.
- **`openEventInspectionSheet(item)`**: Centered modal sheet with responsive grid layout and fleet action triggers.
- **`renderTraffic()` Drawer & Table Upgrades**:
  - Adds attribution badge and hash badge to the "Process / Domain" table cell.
  - Adds lineage tree, provenance metadata, command line, and forensics launcher to `.flow-drawer`.
  - Supports `tf.hash`, `tf.user`, and `tf.attribution` filter chips in the top filter bar.
- **`renderRoute()` Recent Flows Integration**:
  - Adds attribution badges and an "Inspect" forensics button to each row of the Asset "Recent flows" table.

### 2.2 Backend Storage & API Query Parity (`hub/pkg/storage/traffic.go` & `hub/pkg/server/traffic_api.go`)
- Extended `TrafficFilter` with `ExecutableSHA256`, `UserIdentity`, and `AttributionStatus`.
- In `buildTrafficWhere`:
  - `executable_sha256 = ?` (with case normalization).
  - `user_identity = ?`.
  - `attribution_status = ?`.
- In `parseTrafficFilter`:
  - Parses `executable_sha256` / `hash`, `user_identity` / `user`, and `attribution_status` / `attribution`.
