## Claims

1. **Linux IR Standard Profile Collectors**:
   - Implemented 4 incident-response collectors in `agent/include/forensics_linux.h`:
     1. `persistence.json`: Scans and captures autorun mechanisms: `/etc/ld.so.preload`, `/etc/rc.local`, `/etc/profile.d/`, enabled systemd service units from `/etc/systemd/system/`, and SysV init scripts from `/etc/init.d/`.
     2. `scheduled_tasks.json`: Parses `/etc/crontab`, individual `/etc/cron.*` directories, and systemd timer units from `/etc/systemd/system/` and `/lib/systemd/system/`.
     3. `security_events.txt`: Collects recent authentication and security event log entries from `/var/log/auth.log`, `/var/log/secure`, `/var/log/syslog`, or `/var/log/messages`, bounded to 128 KiB with honest `truncated` status reporting.
     4. `shell_history.txt`: Reads root and user interactive shell histories (`/root/.bash_history`, `/home/*/.bash_history`, `/root/.zsh_history`), bounded to 32 KiB with honest `truncated` status reporting.
   - Together with 8 diagnostic items and 6 live volatile items, the `ir_standard` profile collects 18 distinct artifacts in a single atomic pass.

2. **Windows IR Standard Profile Collectors**:
   - Implemented 4 incident-response collectors in `agent/include/forensics_windows.h`:
     1. `persistence.json`: Scans Registry Run and RunOnce keys (`HKLM\Software\Microsoft\Windows\CurrentVersion\Run`, `RunOnce`, `HKCU\...`), Winlogon keys (`Userinit`, `Shell`), and Startup directory files (`C:\ProgramData\Microsoft\Windows\Start Menu\Programs\Startup`).
     2. `scheduled_tasks.json`: Traverses `C:\Windows\System32\Tasks` directory and queries `HKLM\SOFTWARE\Microsoft\Windows NT\CurrentVersion\Schedule\TaskCache\Tree`.
     3. `security_events.txt`: Reads the tail of Windows Security and System event logs via native Win32 `OpenEventLogA` / `ReadEventLogA`.
     4. `shell_history.txt`: Collects PowerShell command histories (`ConsoleHost_history.txt` under `C:\Users\*\AppData\Roaming\Microsoft\Windows\PowerShell\PSReadLine`).
   - Supports single-pass 18-artifact collection via `Forensics_RunIRStandardCollectionWin`.

3. **Hub Evidence Items Query API**:
   - Added `GetBundleItems(tenantID, bundleID)` in `hub/pkg/evidence/store.go` querying registered artifacts for an evidence bundle with strict tenant isolation.
   - Added `GET /api/v1/evidence/items?bundle_id=` in `hub/pkg/server/evidence_handlers.go`.
   - Verified via unit test `TestServer_EvidenceItemsQueryAPI` in `hub/pkg/server/evidence_test.go`.

4. **Web Console UI Integration**:
   - Added `launchForensicsSheet(asset)` in `hub/pkg/server/web/app.js`:
     - Checks and enforces response authority unlock.
     - Selects profile (`diagnostic`, `live_volatile`, `ir_standard`) with dynamic descriptive guidance.
     - Configures size bounds (512 KiB default, up to 10 MiB bundle cap) and timeout (120s default).
     - Computes SHA-256 payload digest and signs WebCrypto Ed25519 ActionProof V2.
     - Posts to `/api/v1/response/jobs`.
   - Added `openLaunchForensicsPicker()` for target endpoint selection.
   - Added "Collect Forensics…" to asset action menu in Hosts view and to Forensics section header.
   - Upgraded Forensics table in `renderForensics()`:
     - "Inspect" button opening `inspectBundle(bundleId)`.
     - Manifest artifacts table showing all items, status badges (`badge-ok`, `badge-warn`, `badge-crit`), formatted sizes, content types, and SHA-256 hashes.
     - "Toggle Hold" button invoking `toggleBundleHold(bundleId, hold)` via `POST /api/v1/evidence/bundles/hold`.

5. **Hub End-to-End Integration Test**:
   - Added `TestServer_IRStandardForensicFlow` in `hub/pkg/server/response_test.go`.
   - Proves the entire 18-artifact flow: Response Authority session unlock, typed ActionProof V2 signing, job creation with profile `ir_standard`, offer delivery, 18-artifact upload, canonical manifest V2 signing with TweetNaCl, manifest verification with stored endpoint key, receipt issuance, items API query, and decrypted `.tar.gz` export verification.
