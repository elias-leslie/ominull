## Claims

1. **Three Independent Certificate Sources**:
   - **Source A (Operator-supplied)**: Configured via `--console-tls-cert` and `--console-tls-key`.
   - **Source B (Automated ACME DNS-01)**: Built native ACME DNS-01 package `hub/pkg/acme` using `golang.org/x/crypto/acme`. Configured via `--acme-enabled`, `--acme-domain`, `--acme-email`, `--acme-dns-provider cloudflare`, `--cloudflare-api-token`. Issues Let's Encrypt certificates using DNS TXT challenges, atomically persisting to disk with 30-day automatic renewal threshold.
   - **Source C (Hub CA Leaf with Guided Root Trust)**: Issues an internal CA leaf certificate with SANs covering `--console-hostname` and interface addresses.
2. **WebAuthn RP ID Invariant & Hostname Capture**:
   - `configuration.Config.Validate()` enforces that `ConsoleHostname` must be a valid DNS domain name and strictly rejects IP addresses, satisfying W3C WebAuthn RP ID requirements.
   - Post-install setup wizard (`/setup`) prompts for `console_hostname` with an explicit warning that changing the hostname later invalidates all enrolled WebAuthn passkeys.
3. **Root Trust Guidance & Operator CLI Parity**:
   - `ominullctl console export-ca [--out FILE] [--path PATH]` extracts the hub root CA certificate directly from disk or remotely via `/api/v1/pki/ca.crt`.
   - `ominullctl console trust-instructions` and `GET /api/v1/console/trust-instructions` output OS/browser-specific installation commands for Debian/Ubuntu, RHEL/Fedora, macOS, Windows, Chrome, and Firefox.
   - `ominullctl console status` and `GET /api/v1/console/status` surface the listener address, hostname, WebAuthn RP ID, TLS source mode, HSTS state, and client certificate isolation.
4. **Clean Packaging & Lifecycle**:
   - Packaging templates updated with default `OMINULL_CONSOLE_TLS_LISTEN=:8443` and `OMINULL_CONSOLE_HOSTNAME=hub.lan`.
   - Passed package lifecycle tests (MSI, Debian registration, upgrade, downgrade refusal, identity and PKI preservation).
