# Evidence: Slice 7C — CPE Version Range Comparison & Explainable Correlation Matching Engine

## 1. Overview

Slice 7C implements the authoritative CPE 2.3 parser, multi-system version range comparison engine, and explainable vulnerability correlation matcher in `hub/pkg/vuln/`.

Unlike simplistic prototype substring matching or heuristic banner regexes, this engine enforces:
1. **CPE 2.3 & 2.2 Specification Conformance**: Formatted string binding (`cpe:2.3:part:vendor:product:version:...`) and URI binding (`cpe:/...`) parsing with escape-sequence unescaping (`\:`, `\\`), wildcard resolution (`*`, `-`), and package alias normalization.
2. **Deep Packaging Version Comparison**:
   - **Debian Rules (§5.6.12)**: Handles integer epochs (`1:8.9p1`), upstream versions, and debian revisions (`-3ubuntu0.6`), recognizing that hyphens followed by non-digits designate upstream prerelease tags rather than debian revisions.
   - **Tilde & Prerelease Sorting**: Evaluates `~` (which sorts before empty string/all versions, e.g. `1.0~rc1` < `1.0`), SemVer prereleases (`alpha`, `beta`, `rc` sort before release, e.g. `2.0-beta9` < `2.0`), and patch suffixes (`p1`, `p2` sort after base, e.g. `1.8.31` < `1.8.31p1` < `1.8.31p2` < `1.8.32`).
   - **Windows Dotted Numeric Versions**: Dotted component comparisons (`10.0.19041.1200` < `10.0.19041.1300`).
3. **Strict Range Boundary Evaluation**:
   - Compares installed versions against `versionStartIncluding`, `versionStartExcluding`, `versionEndIncluding`, and `versionEndExcluding`.
   - Distinguishes 4 exact match candidate states: `matched`, `not_affected`, `possible`, and `insufficient_data`.
4. **Independent Source Values & Transparent Prioritization**:
   - Preserves `cvss`, `is_kev`, `epss`, `severity`, and `confidence` as distinct first-class database columns and JSON fields.
   - Computes an explainable composite `priority_score` (0.0 to 100.0) combining base CVSS (up to 60.0), CISA KEV exploitation (+25.0), and EPSS probability (up to 15.0), scaled by correlation confidence.
5. **Auditable Explainable Evidence**:
   - Serializes `VulnerabilityMatchEvidence` into each match record, specifying the exact software ID, package version, raw version, matched CPE, boundary range, version comparison rationale, and feed snapshot ID.

## 2. Implementation Architecture

### 2.1 CPE 2.3 & URI Parser (`hub/pkg/vuln/cpe.go`)
- **`ParseCPE(raw string) (*CPE23, error)`**:
  - Parses formatted string (`cpe:2.3:`) into 11 components: `part`, `vendor`, `product`, `version`, `update`, `edition`, `language`, `sw_edition`, `target_sw`, `target_hw`, `other`.
  - Splits tokens respecting `\` escape sequences.
  - Unescapes `\:` and `\\`.
- **`MatchesProduct(vendor, product string) (bool, float64)`**:
  - Normalized case-insensitive matching.
  - Suffix matching (`openssh-server`, `openssh-client` -> `openssh`).
  - Library ABI numbering (`libwebp7`, `libwebp-dev` -> `libwebp`).
  - Well-known alias resolution (`apache2`/`httpd`, `nginx-core`/`nginx`, `xz-utils`/`xz`/`liblzma5`).

### 2.2 Version Comparison Engine (`hub/pkg/vuln/version.go`)
- **`ParseVersion(v string) *ParsedVersion`**:
  - Extracts epoch (if preceded by `:` and numeric).
  - Extracts Debian revision if preceded by `-` and starting with a digit.
  - Tokenizes upstream into alternating numeric, tilde, prerelease, and patch tokens.
- **`CompareVersions(v1, v2 string) int`**:
  - Returns `-1` (`v1 < v2`), `0` (`v1 == v2`), or `1` (`v1 > v2`).
  - Handles tildes, prereleases, numeric magnitude, and patch numbers.
- **`EvaluateVersionRange(installedVer string, criteria CPEMatchCriteria) (MatchStatus, string, string)`**:
  - Evaluates `versionStartIncluding`, `versionStartExcluding`, `versionEndIncluding`, `versionEndExcluding`.
  - Returns verdict (`matched` or `not_affected`), human-readable rationale, and range string (e.g. `[8.5p1, 9.8p1)`).

### 2.3 Explainable Match Evaluation (`hub/pkg/vuln/match.go`)
- **`CalculatePriorityScore(cvss float64, isKEV bool, epss float64, severity string, confidence float64) float64`**:
  - Transparent formula: `score = (cvss * 6.0) + (isKEV ? 25.0 : 0.0) + (epss * 15.0)`.
  - Multiplied by `confidence` if < 1.0. Bounded between 0.0 and 100.0.
- **`CorrelateSoftwareItem(sw InstalledSoftware, v Vulnerability, snapshotID string) *VulnerabilityMatch`**:
  - Evaluates all CPE match criteria in vulnerability definition.
  - Generates structured JSON evidence (`VulnerabilityMatchEvidence`).

### 2.4 Hub Database Schema & Store (`hub/pkg/vuln/store.go`, `dto.go`)
- Additive columns on `vulnerability_matches`:
  - `cvss REAL DEFAULT 0.0`
  - `epss REAL DEFAULT 0.0`
  - `priority_score REAL DEFAULT 0.0`
  - `feed_snapshot_id TEXT DEFAULT ''`
  - `evidence TEXT DEFAULT ''`
- Indexes:
  - `idx_vuln_matches_status ON vulnerability_matches(tenant_id, endpoint_id, status)`
  - `idx_vuln_matches_priority ON vulnerability_matches(tenant_id, priority_score)`
- Methods:
  - `CorrelateEndpoint(tenantID, endpointID string) ([]*VulnerabilityMatch, error)`
  - `CorrelateEndpointWithSnapshot(tenantID, endpointID, snapshotID string) ([]*VulnerabilityMatch, error)`
  - `ListMatches(tenantID, endpointID string) ([]*VulnerabilityMatch, error)`
  - `ListMatchesFiltered(tenantID, endpointID string, status MatchStatus) ([]*VulnerabilityMatch, error)`:
    Orders by status severity (`matched` > `possible` > `insufficient_data` > `not_affected`), then `priority_score DESC`, `cvss DESC`.
