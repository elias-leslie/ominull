## Status claimed

`verified`. Implemented the bounded resumable chunked evidence upload pipeline in `hub/pkg/evidence` and integrated with `hub/pkg/server/evidence_handlers.go`. Upload requests are bounded with `http.MaxBytesReader` (max 8MB per chunk), byte ranges and chunk digests are durably tracked in SQLite (`evidence_chunks`), overlapping ranges and out-of-bound offsets are rejected (`ErrRangeOverlap`, `ErrInvalidRange`), idempotent retries succeed without corruption, tenant storage quotas and filesystem free space headroom (minimum 50MB) are enforced before accepting uploads, encrypted objects are written atomically using temporary files with restrictive modes (`0600`), `fsync`, symlink avoidance, and atomic rename (`os.Rename`), per-item data keys are wrapped with `/var/lib/ominull/evidence.key` and authenticated with length-prefixed binary associated data (`OMINULL-EVIDENCE-ITEM-V1`), wrapped keys are sanitized from API responses, and all store methods enforce strict tenant scoping.

## Claims

1. **Bounded Resumable Chunked Upload**:
   - Replaced unbounded buffering with `http.MaxBytesReader(w, r.Body, 8*1024*1024)`.
   - Supports explicit item creation (`/api/v1/evidence/items?action=create`) and chunked ingestion (`X-Chunk-Index`, `X-Chunk-Offset`, `X-Total-Size`).
   - Tracks received chunks in SQLite (`evidence_chunks`).
   - Enforces range boundaries: `offset >= 0`, `len(chunk) > 0`, `offset + len(chunk) <= total_size`.
   - Validates no overlapping byte ranges against prior recorded chunks (`ErrRangeOverlap`).
   - Idempotent retries of identical chunks succeed safely.
   - Automatically assembles and completes item when all contiguous chunks are received.
2. **Quota & Filesystem Space Enforcement**:
   - Tenant storage quota checked against cumulative `evidence_bundles.total_bytes` (`ErrQuotaExceeded`).
   - Filesystem disk space headroom validated using `syscall.Statfs(storageDir)` to guarantee at least 50MB free disk before writes.
3. **Atomic No-Follow Writes**:
   - Writes encrypted payloads to temporary files in `storageDir` (`tmp_obj_...`) with mode `0600`.
   - Synchronously flushes buffers with `Sync()` (`fsync`).
   - Rejects destination paths that are symlinks.
   - Atomically renames temporary file to final content-addressed digest path (`os.Rename`).
   - Spanning SQLite transactions commit metadata; rolls back and unlinks orphaned object files on transaction failure.
4. **Length-Prefixed AEAD Associated Data**:
   - Eliminated colon-delimited string formatting for AEAD.
   - Uses `CanonicalItemAAD`: length-prefixed `OMINULL-EVIDENCE-ITEM-V1\x00` + tenant_id + bundle_id + item_id + name + offset + totalSize.
   - AES-256-GCM authentication protects data integrity against tampering.
   - Wrapped keys marked `json:"-"` in `EvidenceItem` to prevent secret leakage in API responses.
5. **Strict Tenant Scoping**:
   - Every store method and HTTP handler accepts and verifies `tenantID`.
   - Cross-tenant access to bundles, items, chunks, holds, or exports is rejected with `ErrTenantMismatch` (`403 Forbidden`).
