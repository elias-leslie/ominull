## Status claimed

`verified`. Implemented the durable schema, dynamic additive migrations, telemetry ingestion pipeline, and query projections for process lineage and executable hashes:
1. **Additive SQLite Schema & Dynamic Migrations**:
   - Added 8 enrichment columns to the `events` table with safe defaults:
     - `process_instance_id TEXT DEFAULT ''` (boot_id + pid + start_time)
     - `parent_pid INTEGER NOT NULL DEFAULT 0`
     - `parent_process_instance_id TEXT DEFAULT ''`
     - `command_line TEXT DEFAULT ''`
     - `user_identity TEXT DEFAULT ''`
     - `executable_sha256 TEXT DEFAULT ''`
     - `attribution_status TEXT DEFAULT ''` (e.g. `authoritative`, `inferred_cached`, `race_suspected`, `permission_denied`, `unknown`)
     - `observed_at DATETIME`
   - Added automatic dynamic migrations in `Store.initDB()`: existing SQLite databases transparently migrate without data loss, service interruptions, or manual operator intervention.
2. **Backward & Forward Compatibility**:
   - Old databases without new columns migrate seamlessly on startup.
   - Old agents sending telemetry without enrichment fields continue to ingest cleanly with non-null defaults (`""`, `0`, `nil`).
   - New agents sending enrichment fields are persisted verbatim without blocking or delaying flow ingestion.
3. **Storage Pipeline Integration**:
   - `InsertEvent` and `InsertEventsBatch` in `hub/pkg/storage/storage.go` updated to persist all 8 enrichment fields with parameter binding.
   - `InsertTelemetryBatch` and `IngestTelemetryBatch` in `hub/pkg/storage/telemetry_batch.go` updated to persist all 8 enrichment fields within the atomic transaction.
   - `QueryEvents` in `hub/pkg/storage/storage.go` updated to query all 8 columns using `COALESCE` for non-null strings/ints and `sql.NullTime` for nullable timestamps.
4. **Traffic Analytics & Flow Projection Parity**:
   - Updated `TrafficFlowItem` struct in `hub/pkg/storage/traffic.go` to carry all 8 enrichment fields.
   - Updated `QueryTrafficFlows` and `GetTrafficFlowByID` to select and scan all 8 columns into `TrafficFlowItem`.
5. **API Surface Parity**:
   - `POST /api/v1/events` accepts batches carrying enrichment fields.
   - `GET /api/v1/events` outputs enriched JSON objects.
   - `GET /api/v1/traffic/flows` and `GET /api/v1/traffic/flows/<id>` return enriched flow items.

## Claims

1. **Zero Data Loss on Legacy Migration**:
   - Databases initialized with earlier schemas migrate to include the 8 columns without altering or corrupting existing rows (`TestLineageAndHashing_MigrationCompatibility`).
2. **Precision Roundtrip Preservation**:
   - `process_instance_id`, `parent_pid`, `parent_process_instance_id`, `command_line`, `user_identity`, `executable_sha256`, `attribution_status`, and `observed_at` roundtrip through ingestion, storage, and retrieval without truncation or modification (`TestLineageAndHashing_InsertAndQueryLifecycle`).
3. **Heterogeneous Fleet Telemetry Acceptance**:
   - Batches containing mixed legacy and enriched events ingest within a single transaction without schema rejection (`TestLineageAndHashing_IngestTelemetryBatchCompatibility`).
4. **API Query Parity**:
   - The REST endpoints `/api/v1/events`, `/api/v1/traffic/flows`, and `/api/v1/traffic/flows/<id>` serialize the complete lineage and hash metadata (`TestServer_LineageAndHashing_IngestionAndAPI`).
