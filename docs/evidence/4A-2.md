## Status claimed

`verified`. Implemented the `diagnostic` forensic collection profile on Windows. Collectors capture allowlisted system diagnostic artifacts via native Win32 APIs with honest status attribution (`collected`, `empty`, `unsupported`, `permission_denied`, `truncated`, `timed_out`, `failed`), individual byte caps (512 KiB per artifact), cumulative bundle caps (10 MiB), and execution timeouts. Forensic collection runs inside a dedicated worker thread (`ForensicsWorkerThreadProcWin`) isolating errors and duration timing from the telemetry loop. Manifests are encoded into canonical length-prefixed binary format (`OMINULL-MANIFEST-V2\0`) and signed in-process via TweetNaCl detached Ed25519 using a persistent endpoint evidence key (`C:\ProgramData\Ominull\evidence_signer.key`), seeded by the system BCrypt CSPRNG (`BCryptGenRandom`), advertised to the hub in telemetry batches and verified upon finalization. HTTP evidence artifact uploads and bundle finalization use `Hub_PostPathData` over WinHTTP, inheriting mutual TLS, client certificates, CA pinning, and device credential headers. Fully verified with C unit tests (`-Wall -Wextra -Werror`) under MinGW and Wine, Go integration tests under race detector (`TestServer_WindowsDiagnosticForensicFlow`), and Windows MSI package builds and lifecycle rehearsal.

## Claims

1. **Allowlisted Windows Diagnostic Profile Collectors**:
   - Implemented 8 dedicated Win32 collectors in `agent/include/forensics_windows.h`:
     1. `os_version.json`: Reads `HKEY_LOCAL_MACHINE\SOFTWARE\Microsoft\Windows NT\CurrentVersion` (`ProductName`, `DisplayVersion`, `CurrentBuildNumber`, `EditionID`, `InstallDate`), `GetComputerNameA`, and `GetNativeSystemInfo` for architecture (`x86_64`) and processor count.
     2. `network_interfaces.json`: Uses `GetAdaptersAddresses` from `iphlpapi.dll` reporting adapter names, friendly names, descriptions, formatted MAC addresses, operational status, MTU, and unicast IPv4/IPv6 addresses.
     3. `routes.txt`: Formats `GetIpForwardTable` output into destination, mask, gateway, interface index, metric, and protocol.
     4. `dns_config.txt`: Uses `GetNetworkParams` from `iphlpapi.dll` reporting host name, domain name, DNS servers, node type, and routing/proxy configuration.
     5. `resource_summary.json`: Uses `GlobalMemoryStatusEx` (memory load percent, physical memory, pagefile memory), `GetTickCount64` (system uptime), and `GetDiskFreeSpaceExA` for system drive `C:\` total and free bytes.
     6. `service_state.json`: Uses `OpenSCManagerA` and `EnumServicesStatusExA` from `advapi32.dll` reporting installed Win32 service names, display names, state strings (`RUNNING`, `STOPPED`, etc.), PIDs, and exit codes.
     7. `system_logs.txt`: Bounded Windows event log reading via `OpenEventLogA` and `ReadEventLogA` on `System` and `Application` logs (capped at 128 KiB with fallback to `C:\ProgramData\Ominull\agent.log`).
     8. `agent_diagnostics.json`: Reports agent PID (`GetCurrentProcessId`), module file name (`GetModuleFileNameA`), working directory (`GetCurrentDirectoryA`), agent version (`1.8.3`), endpoint ID, hub URL, and uptime.
   - Collectors return honest status values: `collected`, `empty`, `unsupported`, `permission_denied`, `truncated`, `timed_out`, or `failed`.
   - Strict size bounds: 512 KiB per artifact, 10 MiB cumulative cap for diagnostic bundle.

2. **In-Process TweetNaCl Ed25519 Endpoint Key Management & Canonical Manifest V2**:
   - Seeded via BCrypt system RNG (`BCryptGenRandom(NULL, seed, 32, BCRYPT_USE_SYSTEM_PREFERRED_RNG)`). Zero external OpenSSL or CNG DLL dependencies.
   - Detached Ed25519 keypair generation (`Ed25519_CreateKeypairFromSeed`) and signing (`Ed25519_Sign`).
   - Endpoint evidence key persisted to `C:\ProgramData\Ominull\evidence_signer.key` (with public key hex in `evidence_signer.pub`).
   - Windows agent advertises public key in telemetry heartbeat batches (`evidence_signing_key`), stored in SQLite `endpoints.evidence_signing_key`.
   - Canonical binary manifest format V2 starts with magic prefix `OMINULL-MANIFEST-V2\0`, followed by length-prefixed big-endian string headers (`bundle_id`, `endpoint_id`, `tenant_id`, `job_id`, `profile`), timestamp, item count, and per-item descriptors (`name`, `size_bytes`, `sha256`, `status`).
   - Manifest signed with endpoint private key; signature and public key sent to `/api/v1/evidence/bundles/finalize`. Hub verifies endpoint signature before issuing signed hub receipt.

3. **Authenticated WinHTTP Evidence Transport**:
   - Implemented `Hub_PostPathData` in `agent/src/hub_client.c` supporting binary octet-stream uploads and JSON payloads over WinHTTP.
   - Automatically attaches client certificates, pins the Ominull CA certificate, includes endpoint credential headers (`X-Ominull-Device-Credential` or `X-API-Key`), and handles proxy bypass.
   - Uploads items via `POST /api/v1/evidence/items?bundle_id=%s&name=%s&status=%s`.
   - Finalizes bundle via `POST /api/v1/evidence/bundles/finalize`.

4. **Thread Worker Isolation**:
   - In `agent/src/response_windows.c`, forensic collection runs inside a dedicated worker thread `ForensicsWorkerThreadProcWin` spawned via `CreateThread`.
   - Protects heartbeat and flow collection loops from blocking during disk or network I/O.
   - Measures elapsed time and reports job outcome to `POST /api/v1/response/jobs/result` with duration and `manifest_sha256`.
