# v1.8.26 — Address, finding, and window correctness

Released through the canonical hub-first release script. This checkpoint precedes UDP observation,
Windows IPv6 parity, and the topology renderer overhaul.

## Changes

- Canonical IPv4/IPv6 parsing, mapped-IPv4 normalization, interface-zone retention,
  and collision-free IPv6 asset IDs. Discovery no longer invents a MAC address.
- Address scope is separate from estate membership. Configured estate networks
  and known assets can use public addresses. The topology browser consumes hub
  classification; the router summary independently excludes local and estate
  destinations. Public IPv6 traffic remains visible.
- Policy blocking and containment no longer imply a critical threat-intelligence
  finding. Intelligence enrichment preserves the endpoint-reported action and
  carries the matching indicator into detection. Address suffixes do not establish
  gateway roles; process roles and hostnames do not establish agent coverage.
- Explicit private container CIDRs replace guessed bridge exemptions. A prefix
  extending outside private space is rejected.
- IPv6 audit peers remain intact. Malformed address batches are rejected before
  endpoint or event writes. Event timestamps are stored in UTC.
- Topology and traffic windows count matching observations rather than daily or
  lifetime totals. Rankings, distributions, domain evidence, and chart buckets use
  the selected flow scope. Failed anomaly/distribution/ranking queries return errors.
  The hourly estate comparison includes partial boundary hours and labels event
  counts and its independent scope. Duplicate panels using different scopes are removed.
- Alert search applies before pagination and to its host summary. Page acknowledgement
  freezes visible open IDs at confirmation. Pagination returns to a valid page after
  acknowledgement removes the last page.
- Scanner status reads return a snapshot rather than a concurrently mutated pointer.
- Release requests use a fresh credential descriptor per request. Staging cleanup
  removes explicitly staged artifacts. Previously tracked evidence identifiers are
  anonymized; private deployment details remain outside this repository.

## Regression evidence

Fail-first tests exercised public storage and authenticated HTTP routes. Browser-model
checks cover IPv6 grouping and acknowledgement payloads. Router predicate tests retain
public IPv6 destinations. A release-request fixture verifies three consecutive requests
can each read their credential descriptor.

The scanner regression exposed a worker/status-reader race under `go test -race`.
Returning a status snapshot removed the race in the targeted rerun.

An isolated HTTP test hub served synthetic dual-stack data to managed headless Chrome.
Visual inspection showed local/estate IPv6 hosts separate from the external destination.
The 65-alert fixture showed 15 rows on page 2. Acknowledging those rows left 50 open
and returned to page 1 of 1. Browser error and console checks were empty.

An explicit deployment-maintenance reset was tested on a database copy. Dry-run retained
observations; apply produced a verified backup. All 40 non-observation tables, endpoint
identity, retained asset rows, and operator claims passed preservation checks. Compressed
backup integrity was also checked. This operation is not an automatic migration.

## Verification limits

Synthetic IPv6 fixtures establish ingestion, storage, classification, and rendering
behavior. Native IPv6 traffic and enforcement require the later dual-stack lab checks.
The production reference network is IPv4-only.

## Release checkpoint

All six online endpoints reported v1.8.26 with no provenance issues. The release
script exited after its five-minute convergence deadline because two known powered-off
laptops remained outdated. They remain queued; this is not full-fleet convergence.

All required Go formatting, vet, race, native build, JavaScript syntax, version,
router/release regression, and project checks passed. Staged secret scanning passed;
history scanning found only the documented legacy hit. Repository hygiene passed.

The production maintenance reset removed 5,171,311 old events and related observations.
All 43 preserved-table checks and operator-claim checks passed. An initial large-transaction
attempt exhausted container memory before committing; the old hub restarted successfully.
The corrected helper closes its backup connection and commits bounded deletion batches,
with verified compressed backups retained. No reset runs on ordinary upgrades.

The live console rendered 86 nodes and 44 edges after observations resumed, separated
local address groups from external destinations, and reported zero anomalous or blocked
edges in that sampled window. Browser error and console checks were empty. Visual review
at 1280 by 900 confirms the remaining tiny labels, excess blank space, and clipped metrics;
the planned topology replacement remains necessary.

Release review also found that the hub automatically offers its bundled version to every
outdated endpoint. The release script's canary queue therefore does not enforce staged
rollout. Correct that behavior before shipping the new native collectors.
