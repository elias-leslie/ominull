# Console audit remediation — v1.8.37

Work on the existing telemetry/topology task resumed on 2026-09-09 from clean
`92469d2`. The audited frontend still matched v1.8.36. Phase 4 attribution and
Phase 5 IPv6 work were preserved and not started.

## Changes

- SEC-01: diagnostics navigation uses the signed session at `/status`, never a
  query credential. Removed the unsupported unconditional verification badge.
- UX-07/08: State sorts on its display word; timestamp cells carry epoch sort
  keys. Table controls restore focus after rebuilding.
- UX-09/10: replaced route traps are disposed; detached/background overlays
  cannot trap Tab; account entry/exit restores focus; foreground sheets own
  shortcuts. Navigation and Back/Forward guard dirty drafts and terminal viewers.
- UX-11: endpoint alert counts/rows and 24-hour source flows are requested
  independently of global filters/pages. Raised, unacknowledged alerts use the
  existing endpoint scope and show the total plus latest 50; traffic shows latest
  25 with a matching scoped link. Unmanaged assets explicitly disclose that they
  have no endpoint alert identity; destination references are not relabeled as
  alerts raised on that host.
- UX-01/02: required-resource readiness distinguishes loading, empty, refusal,
  authentication, and failure. HTML/malformed JSON cannot masquerade as arrays.
  Independent completions paint without waiting for optional reads; obsolete
  section reads are cancelled. GET failures retain successful data and expose
  retry/backoff. Requests have a 15-second deadline; mutation timeouts instruct
  the operator to inspect action status before retrying. Empty credential lists
  no longer assert that agents use shared-key authentication.
- UX-03/04/05/06: alert checkboxes have useful names and mixed selection state;
  provenance has accessible names; learning windows render dates/durations;
  compact asset views retain address, host and state; Audit discloses the latest
  100-entry limit. Cursor pagination/export for Audit is not added in this slice.
- PWA-01/02: persistent storage contains only explicitly public assets. HTML
  authentication responses are rejected during installation. Offline navigation
  returns a deliberate public screen with no operator identity or fleet data.
  Cleanup touches only old Ominull caches. Updates require an operator action
  and refuse activation while another window remains open. API requests remain
  network-only. The personalized-cache finding is P2; normal POST sign-in was
  never evidence of a cached-key disclosure.
- PERF-01/02: metadata freshness budgets reduce broad repeat reads. Endpoint,
  asset, scan-result, quarantine, alert and terminal reads remain hot. Topology
  retains its 60-second cache, shares cold builds, exposes snapshot timestamps,
  and returns a body-free 304 for an unchanged validator. Assets mounts at most
  100 rows and reuses unchanged rows, with selection retained across pages.
  Topology and terminal scripts load on demand with loading/error feedback.
- Presentation: expandable labeled navigation, readable type and metric labels,
  visible connection/freshness, alert list/detail and action explanations,
  accessible numeric traffic summaries, simpler response language and explicit
  read-only controls. Response history is labeled as active plus recent history.

## Verification and measurements

Failing reproductions were captured for State sorting, sentinel URL navigation,
route trap disposal, background shortcuts, timestamp sorting, HTML-to-data,
dirty navigation, personalized worker storage, unrelated-cache deletion,
missing offline response, and missing topology validators. The committed browser
suite exercises the actual app with sanitized fixtures. The fixture server
rejects writes and never contacts the live fleet.

- `scripts/check-topology.sh`: topology bundle/model checks, 29 Node tests, and
  11 browser behavioral checks. The browser suite is part of CI in isolated
  Chromium; local execution uses ST's managed headless Chrome profile.
- Full Go vet/race passed; the server package took 231.451 seconds. The native
  build passed. The managed quick gate passed (its Python gates do not apply to
  this Go/JavaScript project). Version/syntax/diff/hygiene checks passed.
- axe WCAG A/AA: 40 fixture pages (five sections × four themes × desktop/compact)
  reported no violations and no document-width overflow. This does not establish
  screen-reader usability or universal accessibility compliance.
- Actual Chromium worker activation preserved an unrelated cache and removed an
  obsolete Ominull cache. With the isolated HTTP origin stopped, reload rendered
  the offline screen with no sentinel operator identity. Browser offline
  emulation alone did not stop the worker's network read, so it was not used as
  evidence of offline correctness.

Comparable final fixture: headless Chrome 152, Linux, 1280×633, no throttling,
six synchronous renders per size, unique host IDs/addresses/MACs, seven unmanaged
assets. Both runs used the same fixture and current presentation assets; only
`app.js` changed from checkpoint `92469d2` to the remediation.

- 14 assets: median 3.05 ms before, 3.50 ms after.
- 100 assets: median 18.95 ms before, 13.30 ms after.
- 1,007 assets: median 178.55 ms before, 21.30 ms after (about 88% lower).
  DOM nodes: 30,495 → 3,275; mounted asset rows: 1,007 → 100.

These are synchronous fixture render timings, not paint, INP, battery results or
production percentiles. Earlier exploratory runs measured 252–403 ms before and
21–39 ms after, with repeated demo addresses; the final unique-address fixture
above supersedes those as the comparable result. The original audit's 315–475 ms
observations remain separate measurements.

## Limits and explicit deferrals

Installed OS/PWA window integration, a real screen-reader pass, Firefox/WebKit,
two real installed windows upgrading with a dirty form, CPU/network throttling,
and a 30-minute memory/battery soak are not established by this run. The worker
implements a minimal offline status screen, not an offline fleet console.

Unmanaged-host alert attribution requires a source identity in retained alert
records; this pass discloses the limit rather than inventing a destination join.
The original topology model and SQL are retained. SQL/query-plan restructuring,
edge compression tuning, audit cursor/export features, density preferences,
and a larger navigation/admin information-architecture move are deferred. The
current scope fixes the documented misleading history limit and implements the
core navigation/readability/triage improvements without those broader changes.

The managed service rebuild was attempted and failed because the workstation has
no configured Ominull service. Production lives in the documented remote LXC;
release uses the canonical Ominull hub-first package workflow instead. This is a
managed-service configuration gap, not a production health failure.

## Release and live results

The canonical `scripts/release.sh --version 1.8.37` completed successfully with
all retained gates, signed packages, isolated package lifecycle, hub-first
installation, explicit Linux/Windows canaries, and the frozen online cohort.
Six online endpoints converged to v1.8.37 with zero provenance issues. Two
initially offline laptops remain pending; their count was not used to shrink the
captured cohort. Deployed `app.js` and `app.css` bytes match the tested checkout.

A live LAN read returned a 3,422,498-byte topology snapshot in 7,176 ms. Its next
conditional read returned **304, zero body bytes, in 2.3 ms**. A request with the
same validator but no authentication returned 401. This proves transfer
avoidance and preserved authorization; it does not show a cold-query speedup.
The LAN response remained uncompressed despite an Accept-Encoding request;
public-edge compression was not verified.

Normal POST key sign-in followed by cookie-only GET returned a console document
without the key. Cookie-authenticated `/status` returned 200 without any query
credential. No live key, cookie or personalized document was saved in evidence.

The sanitized repeat-request trace was 11→6 for Assets, 12→7 for Topology,
14→9 for Traffic, and 15→10 for Policy and Response. These are observed fixture
requests per repeat refresh, not a production requests-per-minute percentile.
First Topology/Policy visits include an additional on-demand request.

Implementation checkpoint `7fbd6d5` passed all jobs in CI run `34393382928`,
including Chromium behavior, native Windows fixtures and package inspection.
Post-release verification adds a deterministic 100-row bound and conservative
250 ms render ceiling in CI (the reference-machine target remains 100 ms), plus
an Assets axe gate. The full 40-page axe/screenshot matrix is separate evidence.
Gitleaks reported only the known historical placeholder in `665795f`; the
real-value hygiene check found no tracked deployment values.

Read-only desktop inventory did expose a production Ominull PWA window. It was
not used for offline/authentication/upgrade experiments: those tests were
restricted to the isolated fixture origin as requested. The available managed
fixture browser is headless, so OS-installed-window lifecycle remains deferred.
