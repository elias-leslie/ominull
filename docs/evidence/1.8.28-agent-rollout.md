# v1.8.27–v1.8.28 agent rollout correctness

Publishing a bundle previously offered it to every outdated endpoint. A named update
request also changed the fleet target. Updates now require an explicitly queued job;
a canary request does not publish a fleet-wide installation request.

The v1.8.27 rollout exposed a second defect: status used the previous fleet target and
could call a canary current before it installed the new bundle. v1.8.28 status uses at
least the bundled version and returns observed endpoint IDs. Release convergence requires
the requested version, a nonempty observed fleet, and every requested canary ID.

Authenticated route regressions reproduced both automatic offers and the stale-target
status error. Release-command fixtures reproduced false success for an empty fleet,
a missing canary, and an old target. The corrected tests pass. An existing availability
test now explicitly queues its update; its version and package assertions remain intact.

Required formatting, vet, race, native build, JavaScript, version, and release regressions
passed in the canonical release. Live v1.8.28 rollout reported two outdated canaries,
then one, then convergence before scheduling six remaining endpoints. All six online
endpoints updated. Two known powered-off endpoints remain pending; complete fleet
convergence is not claimed.

These releases change update authorization and reporting, not native packet collection.
UDP observation and the topology overhaul remain subsequent work.
