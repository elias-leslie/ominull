# Evidence: Slice 6C — Windows Endpoint Process Lineage, ETW Provider, & Executable Hashing

## 1. Overview

Slice 6C delivers Windows boot identity binding, ETW Process Provider integration with snapshot fallback, parent-child process lineage tracking, user token identity resolution, user-space LRU executable SHA-256 hashing, explicit attribution status semantics, and telemetry batch serialization for the Windows endpoint daemon (`ominulld.exe`).

Every active TCP/IP socket flow captured by `PollActiveSocketFlows` in `agent/src/service.c` is enriched with complete process execution provenance:
- **`process_instance_id`**: Unambiguous string identifier `win-<vol_serial>-<boottime>:<pid>:<createtime_100ns>` preventing Windows PID recycling collisions across the life of the OS or across boots.
- **`parent_pid`**: Authoritative parent PID resolved via dynamic `NtQueryInformationProcess(ProcessBasicInformation)` or snapshot fallback (`CreateToolhelp32Snapshot`).
- **`parent_process_instance_id`**: Verifiable parent instance ID `win-...:<ppid>:<parent_createtime_100ns>` or omitted when the parent process has already terminated (zero synthesis of unverified parent states).
- **`command_line`**: Full UTF-8 process command line extracted via dynamic `NtQueryInformationProcess(ProcessCommandLineInformation = 60)` with zero-allocation JSON escaping.
- **`user_identity`**: Process security principal resolved from `OpenProcessToken` -> `GetTokenInformation(TokenUser)` -> `LookupAccountSidA` formatted as `DOMAIN\User` or `User`.
- **`executable_sha256`**: In-process cryptographic SHA-256 digest computed from safely opened executable file handle using Win32 crypto routines.
- **`attribution_status`**: Explicit status classification: `authoritative`, `inferred_cached`, `race_suspected`, `permission_denied`, or `unknown`.
- **`observed_at`**: RFC3339 timestamp of the local observation.

## 2. Implementation Architecture

### 2.1 Boot Identity Binding & Process Instance IDs (`agent/include/process_lineage_windows.h`)
- Windows boot identity is derived deterministically from system volume serial number and system boot time (`GetTickCount64` subtracted from current Unix epoch).
- Formatted as `win-%08lx-%llu`. Cached in `g_WinCachedBootID` for zero overhead on subsequent queries.
- Process instance IDs format as `${boot_id}:${pid}:${createtime}`:
  - `createtime` is the 64-bit creation timestamp in 100ns intervals from `GetProcessTimes`.
  - If a PID is recycled within the same boot, distinct creation times prevent collision.
  - If the endpoint reboots, the boot prefix changes, isolating cross-boot timeline analyses.

### 2.2 Parent PID & Command Line Resolution via Dynamic `ntdll.dll` Lookup
- Resolves `NtQueryInformationProcess` dynamically via `GetProcAddress(GetModuleHandleA("ntdll.dll"), "NtQueryInformationProcess")`.
- Queries `ProcessBasicInformation` (class 0) to extract `InheritedFromUniqueProcessId` without parsing brittle string snapshots.
- Queries `ProcessCommandLineInformation` (class 60) for direct extraction of `UNICODE_STRING CommandLine`, transcoded to UTF-8.
- Falls back gracefully to `CreateToolhelp32Snapshot` if dynamic NT queries fail or access is restricted.

### 2.3 User Token Identity Resolution
- Queries process token via `OpenProcessToken(hProcess, TOKEN_QUERY, &hToken)`.
- Calls `GetTokenInformation(TokenUser)` to extract SID, then resolves domain and account names via `LookupAccountSidA`.
- Formats as `DOMAIN\Account` (or `Account` if domain is empty). If PID is 0 or 4 (System), attributed safely as `NT AUTHORITY\SYSTEM` or `SYSTEM`.

### 2.4 Win32 User-Space Executable Hash Cache (512 Entries)
- Keyed on the authoritative Win32 file identity tuple: `(volume_serial, file_index, file_size, last_write_time)` retrieved from `BY_HANDLE_FILE_INFORMATION`.
- Provides identical semantic guarantees to POSIX `(dev, ino, size, mtime)` without depending on path renames or NTFS hard link ambiguities.
- File size ceiling capped at 64 MiB (`WIN_MAX_HASH_BYTES`) to prevent telemetry stalls.
- Cache hits return the SHA-256 digest with status `inferred_cached` without disk I/O.
- Cache misses stream chunks through `Response_SHA256_Sum` and record as `authoritative`.
- Monotonic access counter `g_WinHashAccessCounter` ensures true LRU eviction on saturation.

### 2.5 Real-Time ETW Process Provider Lifecycle
- Registers ETW session for `Microsoft-Windows-Kernel-Process` GUID `{22fb2cd6-0e7b-4226-a0f7-2d4c022a0044}`.
- If ETW session creation is unavailable (e.g. non-elevated user or Wine emulation), the agent logs graceful fallback and seamlessly uses on-demand Win32 process inspection without failure.

### 2.6 Zero False Inventions
- If process has already exited upon flow polling, status is marked `race_suspected`.
- If access is restricted by Windows security permissions (`ERROR_ACCESS_DENIED`), status is marked `permission_denied`.
- If parent process has exited, `parent_pid` is preserved while `parent_process_instance_id` is left empty rather than fabricating unverified start times.

### 2.7 Daemon Integration
- **`agent/include/agent.h`**: Includes `process_lineage_windows.h` and embeds `PROCESS_ENRICHMENT_WIN Enrichment;` in `OMINULL_EVENT`.
- **`agent/src/service.c`**:
  - Starts ETW tracing in `Service_Run` / stops upon shutdown.
  - In `PollActiveSocketFlows`, inspects process lineage with intra-batch PID deduplication.
- **`agent/src/hub_client.c`**:
  - In `Hub_SendTelemetryBatch`, serializes `process_instance_id`, `parent_pid`, `parent_process_instance_id`, `command_line`, `user_identity`, `executable_sha256`, `attribution_status`, and `observed_at` with zero-allocation JSON escaping.
