## Status claimed

`verified`. Implemented dedicated console HTTPS listener (`--console-tls-listen`, `OMINULL_CONSOLE_TLS_LISTEN`) in `hub/pkg/server/server.go` and `hub/cmd/main.go`, architecturally separated from the agent machine-to-machine transport listener (`:9443`). Enforced strict trust-model separation: the console listener configures `ClientAuth = tls.NoClientCert`, ensuring browsers are never challenged for agent client certificates and are immune to `--client-certs required`. Enforced automatic `Strict-Transport-Security` (HSTS) header injection on console responses to guarantee browser secure-context requirements for WebCrypto and WebAuthn. Verified clean concurrent lifecycle and shutdown in `console_tls_test.go`.

## Claims

1. **Dedicated Console Listener Separation**:
   - Added `ConsoleTLSOptions` (`Listen`, `CertFile`, `KeyFile`, `Hostname`, `Hosts`) and `SetConsoleTLS` on `Server`.
   - Exposed CLI flags `--console-tls-listen`, `--console-tls-cert`, `--console-tls-key`, and `--console-hostname` in `hub/cmd/main.go`.
   - `Server.Start` binds up to 3 independent listeners (agent TLS `:9443`, console TLS, and loopback/LAN HTTP `:9999`) sharing application routing without conflating TLS trust boundaries.
2. **Client Authentication Isolation**:
   - Agent listener (`:9443`) enforces agent certificate verification against the hub internal CA pool (`ClientCAs`).
   - Console listener strictly sets `ClientAuth: tls.NoClientCert` and does not configure `ClientCAs`, preventing browsers from prompting for or failing on client certificates.
3. **Secure Context & HSTS**:
   - Console listener wraps HTTP handler with `withHSTS` middleware injecting `Strict-Transport-Security: max-age=31536000; includeSubDomains`.
   - Ensures browser context satisfies modern browser requirements for WebCrypto (`window.crypto.subtle`) and WebAuthn credentials.
4. **Clean Lifecycle & Shutdown**:
   - `Server.Close()` cleanly shuts down `consoleTLSServer` alongside `tlsServer` and `httpServer`.
