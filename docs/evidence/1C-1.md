## Claims

1. **State Transition Machine Enforcement**:
   - `IsValidTransition` validates state progression: `queued` -> `offered` -> `acknowledged` -> `running` -> `succeeded` / `failed` / `cancelled`, with `cancel_requested` cooperative flow.
   - Terminal states are strictly immutable; invalid transitions are rejected with `ErrInvalidJobTransition`.
2. **Tenant and Endpoint Binding**:
   - Every ACK, progress update, and result submission verifies that the request's tenant and endpoint match the job's assigned tenant and endpoint.
   - Cross-tenant requests return `ErrTenantMismatch`; cross-endpoint requests return `ErrEndpointMismatch`.
3. **Replay & Lease Protection**:
   - Active leases required on ACK and progress updates; expired leases rejected with `ErrLeaseExpired`, mismatched leases rejected with `ErrLeaseMismatch`.
   - Repeated completion of an already terminal job is handled idempotently without error.
4. **Progress Ingestion**:
   - `RecordProgress` tracks progress percentage and status messages, automatically advancing state from `acknowledged` to `running`.
5. **Durable Transition Audit Logging**:
   - SQLite table `response_job_audit` records every transition with timestamp, tenant, endpoint, job ID, grant ID, from-state, to-state, actor, and descriptive details.
6. **Testing & Deployment**:
   - Verified locally with Go race detector (`go test -v -race ./pkg/response/... ./pkg/server/...`).
   - Verified clean Debian package lifecycle build.
   - Deployed to LXC 150; verified schema creation of `response_job_audit` in production `/var/lib/ominull/ominull.db` and uninterrupted fleet operations.
