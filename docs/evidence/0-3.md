## Claims

1. Authored [`docs/RESPONSE_THREAT_MODEL_AND_TRUSTED_ORIGIN.md`](file:///srv/workspaces/projects/ominull/docs/RESPONSE_THREAT_MODEL_AND_TRUSTED_ORIGIN.md) covering all 10 threat scenarios: stolen cookies, static API keys, hub process compromise, hypervisor/root compromise boundaries, signer compromise, malicious operators, tenant crossover, agent compromise, authenticator recovery, and signed updates.
2. Formalized the three independent trust fabrics:
   - **Fabric 1:** Agent Transport PKI (mTLS `:9443`).
   - **Fabric 2:** Console Secure Origin (HTTPS for WebCrypto/WebAuthn).
   - **Fabric 3:** Tenant Response Authority (isolated Ed25519 signing keys).
3. Resolved the trusted-origin architecture per the owner's decision:
   - No external reverse proxy required in default install.
   - No interim stopgap reverse proxy.
   - In-hub dedicated HTTPS console listener with three certificate sources: Operator-supplied PEM, Built-in ACME via DNS-01, and Hub-issued internal CA.
   - Pinned WebAuthn RP ID requirements (valid FQDN required; IP addresses invalid; hostname immutability).
4. Settled the Windows Agent OS floor for interactive shells: ConPTY forces `NTDDI_VERSION >= 0x0A000006` (Windows 10 Version 1809 / Windows Server 2019 Build 17763). Pre-1809 Windows systems remain supported for telemetry and forensic collection, with shells explicitly disabled.
