## Known gaps

1. **The working tree still carries the rebuilt artifacts under released
   filenames.** `dist/ominull-agent_1.8.3_amd64.deb` and the other two are the
   rebuilt bytes, and `dist/SHA256SUMS.txt` is modified to record them. Anything
   that pushes `dist/` at the hub would undo this slice. `dist/` and version
   identity are owned by slice R0.6; until R0.6 lands, do not run a deploy or
   release script against the live hub.
2. **The installed hub package on LXC 150 is still the rebuilt 1.8.3.** `dpkg`
   certifies `db4f5fc9...` as version 1.8.3, and the response-authority service
   it installed is still running. The download directory no longer distributes
   it, which is what R0.1 covers; the installed tree, the package database, and
   the authority service are R0.6.
3. **`windows-laptop-a` was not hashed directly.** It is offline. The
   conclusion that it runs released bytes rests on its update job retiring at
   21:02:22, 38 minutes before the rebuilt MSI existed, plus the absence of any
   later job. Hash it when it returns.
4. **Two pre-1.3.0 agent packages in the download directory have no signature or
   digest sidecar** (`ominull-agent_1.1.0_amd64.deb`,
   `ominull-agent_1.2.0_amd64.deb`). They predate release signing, so there is no
   signed record for them to match. The hub never advertises them
   (`agentUpdateDescriptor` requires both sidecars) and every agent since v1.3.0
   would refuse them, but `/download/` will still hand them to an anonymous
   caller because `downloadArtifact` matches on filename shape. Pre-existing, not
   introduced here. Retiring them is a release-history decision, not R0.1's.
5. **The committed digest record for versions before 1.8.2 is not reliable.**
   `dist/SHA256SUMS.txt` was rewritten several times per release (three different
   records exist for 1.8.2 alone), so for older versions the detached signature,
   not the committed list, is the authority. Every artifact on the hub except the
   two in gap 4 verifies against the pinned key.

## Rollback result

Both directions were exercised on the live hub rather than described.

- Withdrawn state: `/download/` returned **404** for all three artifacts and the
  hub's package diagnostic returned **fail** naming the six missing files. No
  endpoint could converge on v1.8.3 in that state.
- Restored state: `/download/` returned **200**, the fetched bytes hashed to the
  signed release record, and the diagnostic returned **pass**.

The rebuilt bytes are retained at
`/var/lib/ominull/withdrawn/1.8.3-rebuilt-2026-09-02/` (mode 0700, root) at their
original digests, so the pre-change state is reproducible for investigation. It
must not be restored into `--binary-dir`.

Recovery copies of the released artifacts exist in two independent places: the
hub's `--binary-dir` and the operations vault. `/tmp/ominull-release.EnE1kG`,
where they were found, is volatile and is not a copy anyone should rely on.
