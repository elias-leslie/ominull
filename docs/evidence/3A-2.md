## Status claimed

`verified`. Implemented the durable SQLite session store in `hub/pkg/terminal/store.go` with schema `terminal_sessions` and composite indexes for tenant and endpoint state queries. Enforced concurrency caps (maximum 1 active terminal session per endpoint, maximum 4 active terminal sessions per tenant) both in memory and via SQLite count queries. Implemented automated background sweeping with configurable intervals: timing out unpaired sessions after 30 seconds (`connect_timeout`), expiring idle sessions (`idle_timeout`), and enforcing maximum duration (`max_duration_exceeded`), cleanly closing attached WebSocket relays. Implemented startup daemon restart recovery, transitioning dangling `waiting`, `connecting`, or `active` sessions to `failed` with `close_reason = 'daemon_restarted'`. Enforced strict token privacy: plaintext connect tokens are never stored in SQLite (persisting only SHA-256 `TokenHash`), and are excluded from all JSON serializations and session summaries. Verified via unit and integration tests with `-race`, Debian package build, and package lifecycle verification.

## Claims

1. **Durable SQLite Session State Machine (`hub/pkg/terminal/store.go`)**:
   - Manages states: `waiting`, `connecting`, `active`, `closed`, `failed`, `expired`.
   - Persists session metadata, `token_hash`, timestamps (`created_at`, `expires_at`, `idle_expires_at`, `started_at`, `closed_at`), closure reasons, connection states (`operator_connected`, `agent_connected`), and raw `grant_json`.
   - Indexed on `(tenant_id, state)` and `(endpoint_id, state)` for sub-millisecond concurrency cap evaluations.
2. **Concurrency Caps Enforcement (`hub/pkg/terminal/session.go`, `store.go`)**:
   - Strictly enforces 1 active session per endpoint (`max 1 active terminal session allowed per endpoint`).
   - Strictly enforces 4 active sessions per tenant (`max 4 active terminal sessions allowed per tenant`).
   - Creation attempts exceeding these caps are rejected with descriptive errors.
3. **Background Sweeper & Lifecycle Expirations (`hub/pkg/terminal/session.go`, `store.go`)**:
   - Dedicated background sweeper goroutine periodically scans SQLite for expired sessions.
   - Expired sessions transition to `failed` (`connect_timeout`) if unattached after 30s, or `expired` (`idle_timeout`, `max_duration_exceeded`).
   - Attached WebSocket relays are immediately closed with the corresponding reason, stopping rogue processes.
4. **Startup Daemon Restart Recovery**:
   - On hub startup, `initStore()` scans `terminal_sessions` for dangling sessions in `waiting`, `connecting`, or `active` states.
   - Transitions all dangling sessions to `failed` with `close_reason = 'daemon_restarted'`, preventing abandoned shells from blocking new sessions.
5. **Zero Token Exposure Invariant**:
   - Plaintext tokens are ephemeral and never written to the SQLite database.
   - Direct SQL row and column inspections prove that only SHA-256 hex digests (`TokenHash`) exist in storage.
   - Serialization tests confirm that neither the plaintext token nor the token hash leak into JSON or `Summary()` maps.
